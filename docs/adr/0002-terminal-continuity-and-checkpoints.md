# ADR E2: continuity is separate from capture, durability and process recovery

[Assessment and recovery matrix](../engineering/19-engine-build-adopt-redesign-assessment.md#continuity-and-capture-contract) · [Capture policy](../architecture/10-recommended-baseline-and-adrs.md#adr-a6-capture-and-retention-defaults)

Date: 2026-10-15. **Accepted-for-design recovery contract; unimplemented.** [EA1](../engineering/21-ea1-native-worker-results.md) tests live-owner observations and worker loss only; it implements no checkpoint/tail or process recovery. No universal durable terminal checkpoint or deterministic process replay is promised.

Late attachment and frontend restart require a fresh bounded presentation from a live canonical owner. They do not require another terminal parser or a disk transcript. Losing the owner is a different event: continued application input stays disabled while interpretation is unknown. No raw-input bypass, automatic old action/reply retry or grant resurrection.

A clone copies live state under a particular implementation/lifetime. A screen dump reproduces appearance. A terminal snapshot is an encoded interpretation state. A product checkpoint additionally binds interpretation identity/options, geometry/event cut, capture consent, completeness, integrity and the keeper's observed stream frontier. None restores a dead kernel process, filesystem, remote effect or unsent/uncertain action.

libghostty-vt's current binary codec is a promising same-build snapshot mechanism. Its development format is not a stable archival contract. The assessment proves selected native in-memory continuations, including incomplete CSI/UTF-8, not portable complete recovery. No public top-level C clone API was established; encode/decode in memory is an explicit copy with allocation cost. Pin the exact engine build/profile and validate imported state before any admission.

Ordinary output remains bounded memory only. A raw-equivalent snapshot includes secret-bearing cells/history/partial parser data and cannot be written to disk under metadata or filtered-output consent. Memory snapshots count against the same total quotas and do not survive arbitrary process/host loss. Filtered/gapped transcripts are not complete reconstruction histories. Optional full capture can support interpretation replay from a known initial state, suppressing historical replies/effects; it never reexecutes application commands.

A future checkpoint envelope contains: product/codec/engine/profile/Unicode versions and artifact digests; session/incarnation and output/resize/options sequence cut; lengths/caps/content integrity; READY/FINISH or equivalent completeness; capture authority/expiry; last durable and keeper-retained frontiers. No leases, approvals, credentials, file descriptors, callback pointers or frontend focus authority are restored from terminal state. A checksum detects corruption; authentication and hostile-input validation remain separate. Persist atomically with capacity preflight/fsync only where authorized. Do not silently downgrade or load another engine/version into old citations.

Engine loss may be recoverable from an authorized valid checkpoint plus an exact retained tail, or a complete authorized history from the initial state. A memory-only checkpoint/tail in a separately surviving process can offer explicitly bounded continuity only after a fault test proves the cut and gaps. If any required bytes, parser continuation, options or geometry are missing, mark unknown; show inspection and separately authorized process controls, with a new session available. Keeper/process loss, reboot and remote transport loss have their own observed outcomes. Human takeover fences future input and mediated admissions; it does not stop every existing side effect.

Required gates before implementing a recovery claim: continuation/corruption corpus, split-prefix and resize ordering, snapshot/tail race faults, callbacks/reply suppression, partial delivery and request reconciliation, quotas and capture revocation, exact-build restore and unsupported-version refusal, real engine/keeper/broker/UI crashes. Cross-architecture and cross-version portability require their own evidence. Unknown execution must stay visible even when the terminal image looks plausible.
