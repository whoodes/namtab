# EA1: bounded Rust/libghostty-vt worker

Date: 2026-10-15. [Index](../index.md) · [Cleanup prerequisite](20-workspace-organization.md) · [Assessment](19-engine-build-adopt-redesign-assessment.md) · [Ownership ADR](../adr/0001-engine-ownership-and-presentation.md) · [Continuity ADR](../adr/0002-terminal-continuity-and-checkpoints.md)

## Decision and stopping point

Subsequent authorized [legacy-input investigation](23-legacy-input-investigation.md) confirms the intentional encoder policy and public-seam blocker. [ADR E3](../adr/0003-legacy-input-public-policy.md) records the completed decision; historical results on this page and under `evidence/ea1` remain unchanged. No production encoding correction or EA2 work followed.

**EA1 selection gate: FAIL. Stop dependent application work.** The Rust/public-C worker demonstrates the state/render, ownership and representative input/reply seams, but the selected encoder does not meet the required ordinary legacy control-alias profile. This is a compatibility requirement mismatch, not evidence that libghostty-vt's parser is broken. No production frontend, PTY, broker, runtime isolation or recovery implementation follows this result.

**Recommendation:** retain the public core as a promising candidate, and resolve a narrowly specified legacy-input policy before EA2. Prefer a configurable public encoder policy that preserves ordinary Ctrl-I/Tab, Ctrl-M/Enter and Ctrl-[/Escape aliases when enhanced keyboard protocols are absent, while preserving their distinctions when negotiated. First establish whether an upstream-supported public API can provide that policy. The current pin exposes neither a fixterms toggle nor a direct terminal getter for modifyOtherKeys state, although it does expose Kitty flags. An owned compatibility layer would need an explicit bounded design/maintenance decision and a complete source of negotiated modes; do not infer modes from bytes returned by the encoder, scrape formatter output, introduce a second output parser or force users onto raw bytes. If that public seam cannot be obtained within budget, reopen REDESIGN/fork/core selection. Three key aliases alone do not justify a full engine rewrite.

The original xterm serializer X4 remains independently **FAIL**, with its oracle, six fixtures, manifest and original result preserved. No expected-failure test certifies either engine. The earlier EA0 recommendation remains a completed historical assessment; this newer result blocks its progression to adoption.

## What exists

`crates/engine` is one **binary-only experimental package**, depending on `protocol` among application crates. `protocol::internal_engine` owns the private DTOs and generated request/response schemas under `schemas/private/`; clients must not import them. Seven Rust packages and four TS packages now exist. There are no new registry packages or version changes: Cargo.lock adds only the local engine package with existing serde/serde_json/sha2 dependencies. pnpm-lock.yaml is unchanged. The public logical-key enum expands to navigation, F1–F12 and keypad families; its schema/TS output is regenerated. No public protocol is promised stable.

The worker talks only through caller-provided stdin/stdout pipes. It never opens a PTY, dispatches input to an application, grants permission, reserves a writer lease, persists terminal data or listens on a socket. This private harness transport is **not implemented broker authentication**. It relies on a trusted test parent and is not a sandbox; a same-user process still has ambient OS privileges. Do not expose this interface to clients or treat `feed` as an application-input bypass. Actual OS enforcement/keeper/broker endpoints remain future work.

The native shim uses public installed headers exclusively. It owns terminal, render state, row/cell iterator and encoder handles. Ghostty allocator/free pairs are kept together; only the enclosing C context uses calloc/free. Partial construction and partial render iteration can be freed. Rust owns a non-null context, frees it once, and marks it non-Send/non-Sync using an Rc marker. All Rust unsafe is confined to `engine/src/ffi.rs`; six existing crates retain unsafe forbidden. `build.rs` invokes the already verified local Zig compiler, compiles the C shim with warnings-as-errors and verifies header/library/compiler digests and library aliases. No bindgen/libclang dependency, private enum numbers, packed-cell bit decoding, source patch or semantics fork was added.

The private adapter budget counts C, its header and the Rust wrapper, including comments and wrapper tests. Exact counts are in `evidence/ea1/provenance.json`; they remain below 800 lines. Worker transport/policy, DTOs, build validation and external tests are separately inventoried. This is an explicit accounting boundary, not an assertion that the whole new package is under 800 lines. Upstream private entrypoints and patches: **zero**.

## Public state and input contract

Wire format: four-byte big-endian length, then UTF-8 JSON. Requests are bounded at 64 KiB before allocation; responses at 2 MiB before writing. Payload struct decoding rejects duplicate/unknown fields, invalid Unicode scalars and enum values. Fieldless operations use empty struct variants because Serde's internally tagged unit variants accepted extra fields despite the enum-level attribute. Malformed payload emits one metadata-only error and closes; invalid/truncated framing closes with exit 2 and no payload echo.

Init binds explicit session/incarnation and geometry. The trusted parent must supply a fresh incarnation for every replacement; the worker cannot detect reuse across its own death. Harness replacements now use distinct IDs and test rejection of an old zero-revision/zero-geometry stamp, rather than relying on a revision mismatch. Durable broker generation allocation remains unimplemented. Version/profile identify this private development contract. Ordered `seq` starts at one; version errors do not consume it, syntactically valid in-order logical requests do, including rejections. No duplicate response cache or automatic retries exist. Every subsequent operation supplies the last confirmed session/incarnation/revision/geometry stamp. Feed and resize increment revision; resize also increments geometry. Counter exhaustion is checked **before** mutation. Wrong/stale stamps reject encoding and shutdown. Broker focus, approvals, ownership and dispatch are intentionally absent, not silently granted by this stamp.

One synchronous owner performs feed → callback collection → response, or render update → complete cell copy → clean. Render traversal cannot be interleaved with mutation. Frames own UTF-8 graphemes, wide/spacer kind, RGB/default-resolved colors, palette foreground index when present, style flags, underline, geometry, cursor visibility/style/blink and password **hint**. Styles are data; passwords/approvals cannot be reliably inferred from opaque output. Old copied frames survive subsequent feeds or owner destruction. No native pointers or borrowed row/cell handles escape. There is no replica parser.

The frame's prototype mode bits are: bit 0 application cursor, 1 application keypad, 2 numeric-keypad override (1035), 3 bracketed paste, 4 focus reports, 5 synchronized output (2026), 6 reverse colors and 7 keyboard-action mode. `ground` reports partial parser state. The frame is an **interpretation observation**, not a claim that a real renderer painted it. A sync-output flag does not implement display holds/timeouts. Default/explicit cursor colors, complete palettes, selection/hyperlink/history/graphics presentation, row-cache IDs and accessible frontend painting remain unqualified. Full copied frames are returned even when dirty=false; shared dirty consumption must not cause another view to miss changes. Dirty is advisory and not a second semantic revision.

Named keys use the same public logical-key enum as foundation inputs. Public terminal-derived encoder options control cursor/keypad, mode 1035, Kitty and modifyOtherKeys; the wrapper does not reconstruct them. ASCII character chords map to known public key names with supplied logical text/unshifted codepoint; they do not decode a hardware layout. Non-ASCII modified character chords are refused. Committed text uses the encoder per Unicode scalar, with no implicit modifier; that is a bounded synthetic commit profile, not IME/grapheme/key-release certification. Only press events are advertised. Repeat/release, modifier-side/lock identity, arbitrary layouts, dead keys and host Escape ambiguity remain unsupported/unqualified.

Paste rejects C0/C1 controls except Tab/CR/LF, including embedded bracketed-paste delimiters. It copies the input and calls the pure public paste helper. The declared profile normalizes LF to CR without bracketed paste; with mode 2004 it preserves the tested LF and adds delimiters. This is a disclosed input policy, not silent sanitization or command safety. Focus emits only with mode 1004 enabled. Mouse covers left/right/middle press/release, zero-based cell positions mapped through fixed 8×16 synthetic cell metrics; public mode-derived encoders handle tracking/format. Motion, scrolling and real pixel/outer-terminal mapping are not claimed. Keyboard-action mode refuses key encoding; it is not an approval/security boundary.

No input bytes are written to a PTY. Encoding success proves a pure byte result, not application delivery, transition or termination. Ctrl-C remains a key, not a termination guarantee. Human takeover/leases/observation races require the separate broker and frontend gates. Synthetic existing console/desktop normalization is checked for three common keys and fed through this one worker encoding contract in normal/application-cursor modes; it does not certify complete frontend parity or real focus behavior.

## Replies, bounds and continuity

The only installed reply callback copies bytes synchronously into a fixed 4096-byte C buffer. It allocates nothing, performs no I/O, enters no Rust callback, and never reenters Ghostty. Application-input helpers are pure functions rather than high-level terminal input helpers that might invoke the reply callback. Only feed/resize authorize a callback in the shim. Clipboard/window/file/title effects have no callback authority; graphics storage and file/temp/shared-memory media are explicitly disabled, APC buffering is capped and title reporting is disabled. Unrecognized sequences remain data. This does not certify every hostile parser path or total process memory.

A response exposes terminal replies in one separately labeled batch with its work sequence. Callback chunking is not a logical-query count. Two identical DSR queries yield two concatenated replies, without byte deduplication; observing or resending an old sequence emits none. A reply may need future keeper reconciliation; this worker provides no exactly-once PTY delivery. A parent that loses a response must mark delivery unknown rather than resending a non-idempotent sequence.

Caps: geometry ≤240×100 and ≤4096 cells, feed ≤8192 bytes, scrollback configured to 64 KiB, continuation tracking 4096 bytes, cell UTF-8 copy ≤128 bytes, callback batch ≤4096 bytes. Overflow/native processing/render errors latch unknown, destroy interpretation and return no falsely complete frame, reply or application bytes. There is no raw bypass from unknown. A partial reply buffer is never presented as complete. These caps bound this seam's buffers, **not total RSS, parser CPU, native allocations or all future sequences**. No hostile allocator-failure/ASan/fuzz campaign or many-session performance qualification occurred.

The worker uses blocking pipe writes and at most one in-flight response; slow readers backpressure it. Small-read tests prove framing of a frame larger than a pipe, not latency/deadline guarantees. The trusted parent must bound its own queue and supervise stalled/dead workers. Transport errors do not preserve a process result. No adaptive scheduler, cancellation of native parsing or deadline-enforced runtime exists.

Late reads of a live owner require no transcript, snapshot or disk capture. Killing this worker loses its memory; a new worker starts blank with a newly assigned incarnation. No engine-crash reconstruction, checkpoint/tail cut, keeper/process recovery, persisted snapshot or replay is implemented. Same-build snapshot evidence remains the earlier C assessment, **not** a stable cross-version checkpoint or proof of this worker's recovery. New session initialization is not restoration of lost effects.

## Primary-source audit and second review

Used the exact verified local source/header family, not a moving upstream tip: [public render API](https://github.com/ghostty-org/ghostty/blob/22fa134a07f5749edd9e92c6bc17d8aaf61843be/include/ghostty/vt/render.h), [terminal modes/effects](https://github.com/ghostty-org/ghostty/blob/22fa134a07f5749edd9e92c6bc17d8aaf61843be/include/ghostty/vt/terminal.h), [key event text contract](https://github.com/ghostty-org/ghostty/blob/22fa134a07f5749edd9e92c6bc17d8aaf61843be/include/ghostty/vt/key/event.h), [public encoder options](https://github.com/ghostty-org/ghostty/blob/22fa134a07f5749edd9e92c6bc17d8aaf61843be/include/ghostty/vt/key/encoder.h), [intentional fixterms implementation/tests](https://github.com/ghostty-org/ghostty/blob/22fa134a07f5749edd9e92c6bc17d8aaf61843be/src/input/key_encode.zig), [development snapshot API](https://github.com/ghostty-org/ghostty/blob/22fa134a07f5749edd9e92c6bc17d8aaf61843be/include/ghostty/vt/snapshot.h). No new claim about current released SDK maturity is made. Source remains unmodified; no upstream contact occurred.

Adversarial review repaired: fieldless enum unknown-field acceptance; stale shutdown terminating the worker; sequence/geometry overflow after mutation; native iterator mutation exposure; unverified shared-library aliases; implicit graphics/file policy; complex transport-result representation, reuse of a fixed test incarnation that could mask restart-fencing gaps, and an overwritten test-strategy page detected by link checks and restored from the verified checkpoint. The first control-alias diagnosis blamed missing physical-key mapping; reading upstream source and retesting with known public key names showed that this is **intentional fixterms behavior**, and the revised conclusion retains the failing requirements. No handwritten escape substitution or private encoder access makes the gate appear green.

Residual risks remain explicit: development ABI/codec churn, borrowed native API safety beyond these tests, allocation/CPU faults, partial transport outcomes, interpreter loss, exact-build artifact portability, native library load tampering outside containment, incomplete observation metadata/presentation, enhanced keys/layouts/IME and frontend authority integration. These are not waived by useful seam results. The next step is a concrete input-compatibility decision/gate; **EA2 and broader product implementation are stopped**.
