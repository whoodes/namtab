# Dependency choices, provenance and supply chain

[Index](../index.md) · [Repository](14-repository-and-engineering-practices.md) · [CI](16-test-and-ci-strategy.md) · [Current reuse/source ledger](../engine/research.md)

**Dependency admission policy, not a shipping SBOM.** [E4](../adr/0004-owned-agent-native-engine.md) selects owned Rust semantics; xterm/libghostty/Zig remain historical experiments. No legacy core is a fallback authority. Current exact dependencies are in Cargo/pnpm/docs lockfiles and [dated foundation provenance](18-foundation-gate-results.md#locked-tools-dependencies-and-provenance); EA1 adds a local package and a separately pinned artifact, not new registry records. Tables distinguish these pins from **proposed, unselected** product dependencies. “Unknown” means no product artifact is selected, not that an installed version was measured as latest.

Primary references were inspected in the completed 2026-10-15 campaigns; this consolidation performs no new retrieval. License labels and qualitative replacement costs are evidence-limited, not transitive legal/security clearance. [Owned-core reuse candidates](../engine/research.md#reuse-presentation-storage-and-security-sources) include Unicode primitives and rustix; do not admit them implicitly or mix Unicode table versions. The initial FSM is owned; no emulator or lexer-private continuation becomes authority.

## Rust TUI choice

| Choice | Verified basis | Maintainability/interoperability assessment | Accessibility and decision |
| --- | --- | --- | --- |

Gate actual host/screen-reader operation plus linear review mode; no automatic accessible-terminal claim |

Sources: [Ratatui installation](https://ratatui.rs/installation/), [backends](https://ratatui.rs/concepts/backends/), [Ratatui repository/license](https://github.com/ratatui/ratatui), [Crossterm](https://raw.githubusercontent.com/crossterm-rs/crossterm/master/README.md), [Cursive compatibility](https://github.com/gyscos/cursive/blob/main/README.md), [manifest](https://raw.githubusercontent.com/gyscos/cursive/main/cursive/Cargo.toml), [tui-realm](https://github.com/veeso/tui-realm).

Do not use old tui-rs solely because a tutorial names it. Do not add ncurses, Termion, Termwiz and Crossterm simultaneously to chase theoretical compatibility. A Termwiz/backend comparison is justified only by an essential TERM/encoding gap in NG2/NG3; it is not a second authoritative emulator. Ratatui warns that incompatible Crossterm versions maintain separate event/raw-mode state. The pinned pair is a foundation/research anchor, not a claim every latest crate or release works together. The whole project's compiler floor may exceed Ratatui's minimum.

## Pinning, provenance and upgrade policy

Commit one Cargo.lock and one pnpm-lock.yaml; enforce locked/frozen resolution in CI. Pin direct JS dependencies and build tools to exact artifacts, workspace references explicitly local. Cargo manifest ranges can remain compatible while the committed application lock is authoritative; source overrides/Git dependencies require immutable commits and written rationale. Toolchain, package-manager binary, Electron/Node and runtime image digests are part of the release manifest. A lockfile proves selected bytes/identities only to its integrity mechanism; it is not vulnerability or build-script clearance.

pnpm 10.32.1 is selected and its local tarball integrity verified; ignoreScripts is enabled and every actual install also passes --ignore-scripts explicitly. Explicitly deny unreviewed dependency scripts and permit only named exact reviewed builds (for example packaging/download steps whose artifacts are verified); never blanket allow. Upstream docs describe multiple release lines (including v11 changes); those settings are not a claim about the pinned v10 binary. Verify policy syntax/effect with the selected manager, disable automatic linking of dependency-supplied agent skills where supported, and reject ignored policy controls. A package's SKILL/config file is data, not contributor authorization. Proposed update age delay is seven days with explicit time-limited security-fix exceptions; it reduces exposure, not a safety guarantee. [pnpm build policy](https://pnpm.io/settings/build), [resolution/age policy](https://pnpm.io/settings/dependency-resolution)

Rust build.rs/proc macros and JS install/build tools execute code: run them in clean limited CI with no user/provider secrets, reviewed network/cache access and bounded output. Untrusted PRs cannot access signing keys, privileged runtime hosts or trusted cache writes. Pin external CI actions by reviewed commit and keep permissions minimal. [GitHub secure-use guidance](https://docs.github.com/en/actions/reference/security/secure-use)

Dependency updates are separate, small PRs with lock diff, license/advisory review, toolchain changes, conformance lane and upgrade evidence. Terminal/decoder/runtime/store changes always run extended contracts; auto-merge does not waive them. Track an owner, replacement seam, risk exceptions and expiry for each high-cost dependency. Scan actual packaged Rust binaries, JS bundles, embedded runtimes, native libraries and generated/vendored sources for an SBOM and notices; lock-only reports miss content. SPDX/CycloneDX output can have documented catalog gaps and is not proof of reproducibility or security. Release gates reject unresolved material license/provenance issues; project-license adoption remains a separate owner decision.
