## Rust TUI choice

| Choice | Verified basis | Maintainability/interoperability assessment | Accessibility and decision |
| --- | --- | --- | --- |
| **Ratatui + Crossterm** | Official installation docs pair Ratatui 0.30.2 with Crossterm 0.29 and require Rust ≥1.88; MIT projects; TestBackend exists | Recommended immediate-mode rendering with an application-owned event/reducer loop; more explicit form/focus work, less framework state. One Crossterm version/event reader; Unix/Windows backend paths still require product tests | No native semantic accessibility tree established. Gate actual host/screen-reader operation plus linear review mode; no automatic accessible-terminal claim |
| **Cursive** | Upstream uses Crossterm by default and offers other backends; inspected manifest 0.21.1, MIT | Credible prebuilt dialogs/widgets/theme path; callback/view state must remain client-only. Backend changes affect key/resize behavior; UTF-8 and terminal shortcut caveats are documented | Could reduce forms work, but does not establish better screen-reader behavior. First fallback for a demonstrated control-widget maintenance blocker, not an emulator replacement |
| **tui-realm** | Upstream describes Ratatui components with messages, focus and update routines; MIT | Useful component layer, but adds framework state, companion crates and version coupling. Not needed until concrete repetition justifies it | Adds no demonstrated host accessibility or lost-key recovery. Defer rather than introduce a second client state architecture |

Sources: [Ratatui installation](https://ratatui.rs/installation/), [backends](https://ratatui.rs/concepts/backends/), [Ratatui repository/license](https://github.com/ratatui/ratatui), [Crossterm](https://raw.githubusercontent.com/crossterm-rs/crossterm/master/README.md), [Cursive compatibility](https://github.com/gyscos/cursive/blob/main/README.md), [manifest](https://raw.githubusercontent.com/gyscos/cursive/main/cursive/Cargo.toml), [tui-realm](https://github.com/veeso/tui-realm).

Do not use old tui-rs solely because a tutorial names it. Do not add ncurses, Termion, Termwiz and Crossterm simultaneously to chase theoretical compatibility. A Termwiz/backend comparison is justified only by an essential TERM/encoding gap in PP2; it is not a second authoritative emulator. Ratatui warns that incompatible Crossterm versions maintain separate event/raw-mode state. The proposed pair is a research anchor, not a claim every latest crate or release works together. The whole project's compiler floor may exceed Ratatui's minimum.

## Pinning, provenance and upgrade policy

Commit one Cargo.lock and one pnpm-lock.yaml; enforce locked/frozen resolution in CI. Pin direct JS dependencies and build tools to exact artifacts, workspace references explicitly local. Cargo manifest ranges can remain compatible while the committed application lock is authoritative; source overrides/Git dependencies require immutable commits and written rationale. Toolchain, package-manager binary, Electron/Node and runtime image digests are part of the release manifest. A lockfile proves selected bytes/identities only to its integrity mechanism; it is not vulnerability or build-script clearance.

pnpm 10.32.1 is selected and its local tarball integrity verified; ignoreScripts is enabled and every actual install also passes --ignore-scripts explicitly. Explicitly deny unreviewed dependency scripts and permit only named exact reviewed builds (for example packaging/download steps whose artifacts are verified); never blanket allow. Current docs use allowBuilds and describe newer permissions, while old onlyBuiltDependencies settings were removed in v11. Verify policy syntax/effect with the selected manager, disable automatic linking of dependency-supplied agent skills where supported, and reject ignored policy controls. A package's SKILL/config file is data, not contributor authorization. Proposed update age delay is seven days with explicit time-limited security-fix exceptions; it reduces exposure, not a safety guarantee. [pnpm build policy](https://pnpm.io/settings/build), [resolution/age policy](https://pnpm.io/settings/dependency-resolution)

Rust build.rs/proc macros and JS install/build tools execute code: run them in clean limited CI with no user/provider secrets, reviewed network/cache access and bounded output. Untrusted PRs cannot access signing keys, privileged runtime hosts or trusted cache writes. Pin external CI actions by reviewed commit and keep permissions minimal. [GitHub secure-use guidance](https://docs.github.com/en/actions/reference/security/secure-use)

Dependency updates are separate, small PRs with lock diff, license/advisory review, toolchain changes, conformance lane and upgrade evidence. Terminal/decoder/runtime/store changes always run extended contracts; auto-merge does not waive them. Track an owner, replacement seam, risk exceptions and expiry for each high-cost dependency. Scan actual packaged Rust binaries, JS bundles, embedded runtimes, native libraries and generated/vendored sources for an SBOM and notices; lock-only reports miss content. SPDX/CycloneDX output can have documented catalog gaps and is not proof of reproducibility or security. Release gates reject unresolved material license/provenance issues; project-license adoption remains a separate owner decision.

## EA1 native experiment pin

The experimental binary links official `libghostty-vt` from evaluated commit `22fa134a07f5749edd9e92c6bc17d8aaf61843be`, C ABI SONAME 0.1.0/development source, built with verified Zig 0.16.0, ReleaseSafe and SIMD disabled. The reviewed source archive and compiler hashes remain in the earlier assessment; `evidence/ea1/artifact-pin.json` additionally pins the actual local library, compiler and 35 installed headers. `build.rs` refuses missing/changed material. `evidence/ea1/provenance.json` verifies header correspondence, the loaded library and worker executable. This source is not admitted as a shipping dependency; its input selection gate fails. The upstream MIT metadata and transitive Zig package/license closure remain as assessed in 19, without release/legal clearance or project-license adoption.

Cargo.lock adds one local package only, reusing existing serde/serde_json and sha2 (build verification); all registry records and pnpm-lock.yaml remain unchanged. No bindgen/libclang or new registry tool is required. Portable/reproducible binary hashes, supported SDK release policy, native notices/SBOM and upgrade/ABI review remain open. A new build must receive an explicit provenance review, not an automatic hash refresh.
