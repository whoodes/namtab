## Execution boundary

Unmodified interactive programs receive a real PTY slave with controlling-terminal/session setup, sane initial termios, geometry and an honestly advertised terminal profile. The keeper owns the master. The shell/program owns its normal job-control behavior; it can change termios and its foreground process group. Do not run an emulated shell inside the engine or implement libc/system calls. A terminal is neither the shell's grammar nor its filesystem/environment.

The platform path must handle allocation/setup/exec error reporting, close-on-exec FDs, child reaping, nonblocking partial reads/writes, EINTR/EAGAIN and Linux PTY close/EIO behavior. A process/session leader PID alone is not a safe job-control abstraction. Track runner incarnation and stable handles where supported; observe group/foreground relationships with platform APIs. The keeper must not fight an interactive shell's `tcsetpgrp` transitions. PTY EOF, a child exit, shell job completion, stopped jobs and a drained output frontier are distinct facts (S02–S05).

With ordinary fd 0/1/2 attached to one slave, stdout and stderr are **merged terminal bytes**; their original provenance cannot be recovered. Managed pipe execution preserves separately read stdout/stderr, each with offsets, EOF and timestamps. Their combined UI order is the order the runner observed reads, not a total order of original writes across pipes. Pipes change isatty/buffering/line-discipline behavior; never force pipe and PTY fixtures to have identical output. Programs may open `/dev/tty` or retain FDs in descendants; drain/timeout facts must remain explicit.

Native pipe output is raw stream evidence with a safe text/escaped-control projection by default, not implicitly fed into a legacy terminal model. Structured application records are opt-in typed side-channel data. If a program needs terminal behavior, request a PTY at launch; changing a pipe-backed process into a PTY in place is not supported. Initial pipe stdin is explicitly closed or a bounded predeclared authorized byte payload; general streaming stdin can be a separately scoped later operation, not an application-keystroke route.

Ctrl-C sends a key/input byte according to the profile. Kernel VINTR/ISIG/foreground state may turn it into a signal; the program can change or ignore that behavior. `SignalExecution` and runtime termination are separate granted operations. Group signals do not guarantee all descendants or remote effects stop. Resize records a new canonical geometry cut and a separately observed ioctl result; SIGWINCH/repaint is asynchronous (S03–S06).

Shell integration is optional. v1 candidate adapters report prompt/command boundaries and cwd as attributed hints, without trusting OSC 133/title/CWD text as authority. A stronger execution adapter must use an authenticated execution-bound side channel and still report only what it can observe. Basic shells work without hooks, Zsh, a prompt theme or rc modification. Adapter installation/migration is a later explicit workflow, never startup side effect.

## Profiles and negotiation

Profiles are immutable versioned feature manifests, shared by parser, encoder, terminfo, observations and test matrix. Capabilities distinguish **implemented**, **negotiated**, **available at this endpoint**, and **authorized**. A frontend lacking a physical chord does not remove an inner agent capability. An unsupported profile is refused before launch/input; a well-formed unsupported output sequence follows that profile's documented consume/ignore policy and produces bounded diagnostics, not guessed semantics.

### Syntax, initial state and errors

Notation: `ESC=1b`, `CSI=1b 5b`, `SS3=1b 4f`, `ST=1b 5c`; spaces between tokens are explanatory, not bytes. Coordinates in this contract are one-based. `n` defaults to 1 when omitted or zero; `r,c` likewise. A supported sequence must match its entire private prefix, parameter arity, intermediates and final byte. A default does not authorize extra parameters. Semicolon-separated empty parameters take that row's defaults; colon subparameters are unsupported throughout N1. Bytes are ordered output data, separate from typed application-input operations.

**P malformed syntax:** ESC collects intermediate bytes `20–2f` then a final `30–7e`; CSI collects parameter bytes `30–3f`, then intermediates `20–2f`, then a final `40–7e`. At most one leading private prefix is allowed; a parameter after an intermediate, repeated/misplaced private prefix, or unsupported subparameter makes the sequence ignored through its final. C0/cancel/restart rules below still apply during ignore. A non-ASCII byte during ESC/CSI collection cancels that sequence, discards that byte and records malformed status; following bytes start at ground. **Ignore-state precedence:** once malformed syntax or overflow enters ESC/CSI ignore, non-ASCII bytes are consumed without UTF-8 decoding and do not exit ignore. Ignore ends only at the appropriate final (ESC `30–7e`, CSI `40–7e`), CAN/SUB cancellation or ESC restart; listed C0 controls still execute without ending it. Malformed sequence bytes are not printed as text. This bounded private policy awaits the same review as supported syntax, rather than claiming universal ECMA error recovery.

**P, fixed development bounds:** geometry is 2–200 rows by 2–500 columns, no more than 100,000 cells per grid; reject invalid creation/resize before application. ESC retains at most two intermediates and four total bytes including introducer/final; an excess enters bounded ignore through an ESC final without retaining the run. CSI permits at most 64 parameter fields, each at most five decimal digits and value 65,535, at most two intermediate bytes and 512 total bytes including introducer/final. Any exceeded bound discards that whole sequence through its final byte; CAN/SUB cancels and ESC starts a new escape. Counts do bounded grid work even if large. Unsupported strings retain no payload, only bounded kind/terminator continuation; discard continues across chunks until its terminator, cancellation or stream EOF. These exact dev choices await NG0 review; broader state/history/resource policy remains [N0-05's inventory](#complete-semantic-state), not a new performance claim.

Initial state: primary grid active; both grids blank with default attributes; cursor `(1,1)`, visible, steady block, no pending wrap; primary history empty; full-height vertical region; origin off; autowrap on; normal cursor keys; numeric keypad; backarrow sends DEL; paste/focus reporting off. Each grid owns its cursor, pending wrap, vertical region, tabs and one save slot. Tabs initially occupy columns 9,17,25,… within width. Attributes and input modes are session state unless the table explicitly saves/restores them. No insert/newline mode, left/right margins, character-set switching, keyboard stack or mouse state is active in this profile.

For N1, primary history is capped at 1,000 physical rows; only full-screen primary upward scroll appends history, evicting oldest rows with explicit range unavailability. Partial-region scroll/erase/alternate output never appends. Cropped cells are unavailable, not recoverable hidden rows. The [N0-05 state proposal](#complete-semantic-state) below defines row identities, wrap annotations and anchor invalidation without adding reflow or durable recovery.

## Parser and deterministic application

Recommended starting point: a small owned incremental byte FSM, with a reviewed transition table and semantic dispatch table. Reuse standards techniques, checked UTF-8/Unicode primitives and test generators. Do not import an existing emulator's screen/modes as the authority. vte action dispatch is a useful comparator, but its private continuation makes direct reuse conditional; a maintained lexer dependency is eligible only with a public complete bounded state representation and compatible licensing. No lexer fork or dependency is created in this campaign.

```text
ordered keeper output/resize/control events
    → owned incremental lexer + UTF-8 continuation
    → profile-specific semantic reducer
    → canonical state + immutable observation changes + proposed effects
    → broker fences / keeper delivery (effects), subscribers (observations)
```

One session owner applies an explicitly ordered sequence. Pure reduction is deterministic **only for fixed event order, profile/data versions, initial state and specified limit/error policy**. Clock reads, randomness, OS calls and direct callbacks do not occur inside it. Scheduling, application execution, interleaving of external processes and model behavior are not deterministic replay claims.

That equivalence concerns successful bounded reductions with available resources. It does not promise identical allocation failures, scheduling or OOM behavior across machines. A classified resource failure must refuse/latch the relevant state rather than invent a successful next frame.

### N0-05 bounded continuation proposal

This is the proposed state/FSM design for [N0-05 #11](https://github.com/whoodes/namtab/issues/11), grounded in the finite `px-dev-text-0` manifest above. This is the historical contract/oracle proposal, not evidence of full implementation or qualification. Later bounded N0/MK1 admission and finite core implementation are separate; the complete state contract below remains subject to its validation gates. Values marked P below are deliberate private-profile choices. The complete later v1 inventory remains explicit; an absent feature has an explicit absent/default state, not an undocumented dependency object. No upstream lexer, Unicode data or codec is adopted here.

The byte FSM and semantic dispatch are separate. The FSM emits a complete control/text action only after validating syntax, arity and bounds; the semantic reducer validates the entire action before changing cells/modes or proposing a reply. For example, `CSI 31;3m` changes no attributes because 3 is unsupported; a large CUU clamps once instead of stepping its count. Unknown input caused by missing events is different from bytes intentionally consumed by this specified ignore policy.

| Retained byte state | Bounded fields and transition obligations for the development profile |
| --- | --- |
| Ground / UTF-8 prefix | UTF-8 continuation exists only in ground: retain at most three prefix bytes, expected length and checked scalar/range constraints. On completion emit one repertoire scalar or one width-one replacement. Invalid continuation emits one replacement for the prefix, then processes the offending byte once in ground, including ESC/C0 dispatch; EOF replaces the prefix once. A raw C1 byte never becomes a control. |
| ESC collect / ESC ignore | Retain up to two intermediate bytes and the total length; no payload buffer. Before generic final dispatch, recognize the exact no-intermediate introducers `[` and `]/P/_/^/X`. Unsupported well-formed finals return to ground without effect. Malformed order or length enters ignore. In collect, non-ASCII cancels and discards that byte; in ignore it stays consumed until the ESC final, CAN/SUB or ESC restart. |
| CSI entry / parameters / intermediates / ignore | Retain one optional leading private prefix, presence/emptiness of each field, checked decimal accumulator and digit count, at most 64 fields, up to two intermediates, total length and bounded ignore reason. An entirely omitted parameter list differs from an explicit empty field; the first semicolon materializes the empty first and next fields. Count leading zero digits too. No colon-subparameter storage is admitted: a colon enters ignore. Final dispatch checks exact prefix/arity/intermediates before semantic application. |
| String discard / string discard with pending ESC | Kind is OSC, DCS, APC, PM or SOS; payload retention is **zero bytes**. Preserve the kind and pending-ESC bit at every cut. Backslash after pending ESC ends ST; another ESC leaves pending ESC set; any other byte clears it and remains discarded. OSC BEL ends the string even after pending ESC; BEL in other strings remains discarded. CAN/SUB cancels in either state. Other bytes, including C0/newline, have no screen action. An ESC followed by `[` inside a string never starts CSI. |
| EOF / unavailable interpretation | EOF finishes a pending UTF-8 prefix as above, drops incomplete ESC/CSI/string with one incomplete diagnostic and leaves a closed stream. Repeated EOF is inert; later bytes for that closed stream are refused pending a new valid stream identity. A canonical event gap, broken invariant or unclassified partial mutation latches interpretation unknown and fences every application-input route. A guessed ground state cannot repair it. |

In ESC/CSI collect **and ignore**, the finite manifest's CR/BS/HT/LF/VT/FF/BEL execute without ending the sequence. CAN/SUB cancel it and ESC restarts it before generic byte classes apply. Inside strings only the string rules apply. In ground, CAN/SUB have no glyph; unlisted C0/DEL are ignored. A final that exceeds a byte/count/value bound belongs to the discarded sequence: consume that final and return to ground; do not swallow the next printable byte. Chunk boundaries never synthesize final, cancellation, EOF or ST. Resize, delivery metadata and observations between output events preserve parser continuation; RIS clears it through its complete accepted action.

### Resource limits and failure policy

These are proposed **development safety bounds**, supplementing the unchanged finite table; they are not measured throughput, latency or guaranteed simultaneous capacity. G6 remains the sole product budget owner. The 16 KiB string/256-byte grapheme/16-entry keyboard-stack values formerly mentioned as general candidates do **not** admit those features to N1; the later-profile gates are below.

For this finite reply table, DSR/CPR `CSI 5n`/`CSI 6n` are the shortest supported queries at four bytes; DEC CPR and DECRQM are longer, and DA/other queries emit nothing. A 512-byte event can therefore finish at most 128 queries: even one carried partial query completed by its first byte leaves room for at most 127 more. Any future shorter query, multiple-reply action or changed event/reply bound requires a new reviewed budget proof before admission. Reserving 128 reply slots before event start therefore prevents a queue-full pause from deadlocking an unfinished event. Drain the previous committed event's reply reservations before starting another output event; dispatch uncertainty remains explicit. This conservative event segmentation is a proposed dev choice, with real overhead/usefulness still to qualify.

A byte is inspected at most twice on the invalid-UTF-8 reprocessing path; discard consumes each byte once without a growing count or buffer. A semantic action may visit a bounded grid/history region, so byte limits alone are not a CPU guarantee. Reserve one bounded candidate mutation per session and bound all immutable snapshot/COW views under runtime admission; do not retain an unbounded chain of staged grids. The worker must yield while a large operation is staged, rather than relying on one apparently small escape sequence to be cheap. Future implementation must account for the actual representation/copy costs against G6; these work units are review requirements, not benchmark results.

The public `processed_frontier` names only fully reduced keeper events. Retain one bounded last-committed view or withhold observations while an event is in progress; never expose its newer cells/modes under the previous frontier. Account for the committed view, working event state and one staged mutation under admission, with no unbounded COW generations. A scheduling pause within an output event retains private event identity, immutable event bytes and consumed-byte/action progress; it does not advance that frontier, admit input against the partly applied event or publish its frame. Publish the next frame only after that event is complete. Geometry, replies and application input cannot overtake the unfinished event. Human revoke/cancel admission can remain responsive on its reserved control lane, but does not encode or write application bytes against unprocessed modes. A complete terminal snapshot is taken between completed events with no staged mutation; such a cut may still retain a partial UTF-8/ESC/CSI/ST because a sequence can span events. This makes arbitrary **parser** cuts available without inventing a complete native event cut for half an event. Event numbers, stream byte offsets, semantic revisions and reply ordinals remain distinct. A lost remainder of an in-progress event is a canonical gap, not a transport retry opportunity.

The [N0-06 public stamps](native-contract.md#n0-06-experimental-public-projections-and-intents) require retained canonical counters, not view-local counters. In the proposed dev representation, each buffer kind starts at generation `1`. RIS advances both generations; a first 1049 entry from primary advances alternate before clearing/reinitializing it. Repeated entry while alternate is active is inert. Exit retires and reinitializes the discarded alternate contents, advances its generation, and returns to the unchanged primary generation; a later clearing entry advances alternate again. Resize, ordinary cell edits and DECSTR preserve generations. The generation is scoped by session/incarnation and buffer kind, so equal numbers across buffers are unrelated. Input-mode revision starts at `1` and advances once per committed event if any canonical encoding-mode value changes (cursor/keypad/backarrow/paste/focus in this profile), including a change followed by restoration within that event. Multiple changes in one event produce one bump; no-op commands, transport chunks and scheduling yields do not advance it. These checked u64 values are part of complete semantic state and exact continuation/import validation. Exhaustion refuses the mutation and makes interpretation unavailable instead of wrapping. Fresh session incarnations may start new local counters, while old references remain tied to the retired incarnation.

Inner `capability_revision` instead names an immutable service-owned profile-negotiation record; it is not an extra counter invented by a renderer or reconstructed from cells. A changed advertised interpretation/capability contract needs a new record and the appropriate policy binding. Future admitted dynamic Kitty/MOK negotiation/mode state must be canonical core state, with its own complete-state/reset/continuation rules; this immutable service record is no substitute. Endpoint capability/generation, authority/helper epochs, writer/focus/protection generations and receipt ledgers remain service-owned control state outside a terminal snapshot. Restoring an older complete terminal cut preserves that cut's historical counters; it cannot publish a rewound current stamp or recover a writer fence. Verified ordered tail reconciliation must establish current continuity before input; otherwise keep input fenced or retire the incarnation under the runtime recovery contract. Existing N0-07 projection oracles intentionally exclude such identity counters; they are not counter-lifetime/recovery tests, and those independent tests remain required.

For dev anchors, refer to session/incarnation, buffer, physical row ID, column and semantic revision. Moving a retained row during scroll preserves its ID; history eviction, row removal on resize, buffer reinitialization/1049 discard/RIS retire affected IDs with explicit unavailability. Cell edits, including ED/EL, keep row identity but advance revision, so old cell citations are never silently reinterpreted as unchanged text. Resize preserves IDs in the top-left surviving rows, crops cells permanently, retires removed rows, blanks added cells/rows, and clears wrap flags on both grids; retained history rows keep their captured width and are never reflowed. Presentation may clip a wider historical row but cannot delete its retained cells or reassign IDs. Dev soft-wrap flags are annotations; no selection/search client may join them into new canonical line IDs. Row movement/removal clears a surviving wrap annotation if its formerly adjacent successor changes; explicit cursor movement clears pending wrap, not a historical wrap fact by itself.

Semantic transitions use the finite output table as their only dispatch authority. Ordinary DECSC overwrites exactly one active-grid slot; repeated 1049 entry never pushes a slot; 1049 exit restores the dedicated return state, with the documented invalid-slot fallback. DECSTR preserves cells/history/ordinary saves while resetting both regions/pending flags and invalidating return state; RIS reinitializes both grids/history/modes/parser at current geometry while preserving event/identity continuity and prior diagnostics/evidence. Resize affects both grids/save coordinates even when alternate is active and invalidates the return slot. The cell/history/default-attribute distinctions must survive each transition. No reset changes service epochs, termios or process state.

A reducer transaction either commits a valid complete semantic mutation and proposed effects or latches unknown without exporting a fabricated partial frame. Scratch progress across scheduling yields is owned transient state, never a restorable snapshot or authority to encode input. Derived glyph/search/layout caches can be omitted only if rebuilding them cannot alter canonical text, identities, widths, counters or future effects.

## Unicode, reflow and rendering boundary

For v1, recommend versioned Unicode 18.0.0 data and approved UAX #29/#11 references from S11–S13, with bootstrap hash/license checks and a matching implementation primitive. N1 remains the finite repertoire above. Width is an owned profile: ambiguous width defaults narrow, emoji/variation/ZWJ and combining behavior are explicitly table-driven/tested, not inferred from font metrics. The proposed dev policy tuple is `px-dev-text-0` / `dev-latin1-width-1` / `crop-no-reflow-1`: its finite scalar allowlist needs no imported Unicode conformance tables. A later v1 tuple must name the exact Unicode data hashes/version, UAX revisions, segmentation/tailoring implementation, ambiguous/emoji/private-use/unassigned-width rules and reflow revision; Unicode18 remains a recommendation pending N0-08 pin/review. Changing any admitted semantic policy creates a new tuple, never silently reinterprets a snapshot. No normalization changes application bytes. Invalid UTF-8 has a specified replacement/diagnostic policy and optional authorized raw evidence. Unknown/private-use/unassigned glyph width needs a fixed profile fallback.

Keep stream byte offsets, Unicode scalars, grapheme clusters, logical lines, terminal cells and glyph positions distinct. A cluster may grow across writes; a later variation selector can require a bounded correction to the lead/trailing cells, cursor and delta revision. Editing part of a wide cell clears/repairs the entire occupancy according to a fixture. Leading combining marks and right-edge width changes need hand-authored cases. Reflow cannot rewrite original byte citations.

For v1, primary-buffer soft-wrapped logical lines reflow on resize under the published policy; N1 uses the explicit crop/no-reflow policy above. Hard breaks and alternate-screen content do not magically become reflowable prose. Map history/selection anchors or invalidate them explicitly; cap shrink/expansion work. Resizing and subsequent application repaint are separate events. v1 terminal cells use logical order without full bidi reordering; expose that limitation, safe bidi markers in review chrome, and readable logical inspection. Full bidirectional terminal editing requires a later profile and mapping tests, not an assertion that Unicode storage implies bidi support.

Shaping, font fallback, ligatures and rasterization are presentation concerns constrained by canonical occupancy. They cannot change agent cell positions. Different admitted presentation profiles may paint differently; that is a visible capability/quality issue, not permission for two width authorities.

## Input policy

Keep three planes: namtab UI commands, application input intents, and native automation/control operations. Keyboard packets distinguish named logical key; text/layout facts; optional physical code; modifiers and **consumed** modifiers; composing state; press/repeat/release; endpoint capabilities. Unknown facts stay absent. `CommitText` represents an IME/text commit, not a loop inventing physical key presses; its treatment under report-all/associated-text modes must have a documented encoder contract before that combination is advertised.

The required inner set covers arrows, Tab/Shift-Tab, Enter/Escape, Home/End/PageUp/PageDown/Insert/Delete/Backspace, F1–F12, keypad identities and advertised Ctrl/Alt/Shift chords. A structured key conveys intent and one encoding authority; raw bytes convey an exact authorized payload but require the caller to know its profile. Neither supplies opaque application meaning. Unsupported modifiers, event phases or encodings are refused before writing, without silent raw fallback. `Tab` asks the application to handle Tab; the engine does not run a universal completer. Text preserves declared characters without normalization; ordinary text fields cannot hide C0 controls. Raw application bytes go toward the program, never into the output parser.

The owned encoder reads canonical typed modes directly. Ordinary legacy policy includes Ctrl-I/M/[ → `09/0d/1b`, real Tab/Enter/Escape and documented Alt/Shift/Ctrl behavior. Enhanced Kitty/MOK preserves distinctions after explicit negotiation; no unnegotiated fixterms default. Cover cursor/keypad modes, numlock/backarrow, function keys, consumed Shift/AltGraph/layout facts, per-buffer mode stacks, reset and protocol precedence. N0 must resolve the detailed MOK format/level table before v1; unsupported combinations return a typed capability error before writing, not guessed bytes. Native agents can supply explicit logical keys that the host cannot physically report.

Mouse coordinates bind to geometry/buffer/revision and negotiated tracking/encoding; selection in namtab is distinct from editor selection via keys/mouse. Focus events are protocol hints tied to view identity, not permission. Paste is a separate typed bounded operation: wrapper policy reads **inner** mode, dangerous controls/delimiter injection and newline transformation are explicit, never append Enter automatically. Outer TUI paste wrappers are decoded once, not tunneled inward. Legacy Escape can be a lone key or an Alt/sequence prefix; transport fragmentation and application timeouts preserve ambiguity even after one local write. Outer decoding reports only facts it knows. Enhanced release/repeat distinctions require end-to-end negotiated support; bounded repeated presses remain separate non-idempotent events. Do not infer certainty from sleeps or invent key-up events.

Ordinary paste rejects embedded controls/delimiters unless a separately explicit policy permits them; unbracketed fallback requires declared policy rather than silently pretending equivalence. Record every newline/control transformation in the operation identity. Partial paste can leave incomplete wrappers and uncertain application state. Bracketed paste is not an execution-safety guarantee.

`SendRaw` is a granted bounded compatibility fallback through the same writer/freshness/receipt path. It may have effects the logical encoder cannot describe and must say so; it does not repair a missing canonical state, bypass protected prompts or promise safe retry. An engine in unknown state refuses all application-input routes. Separately authorized OS controls remain possible.

A frontend that knows only the host-resolved `Home` or text `1` sends that fact, without inventing `KP1`. Missing keypad identity cannot be recovered. No `?1035`, `?66` or hardware LED policy. |
| Press/repeat/release | Press emits its payload once. A known repeat event emits the same bytes once and receives its own non-idempotent operation identity; it is not a distinguishable legacy repeat packet. Maximum 64 explicit events per admitted batch, revalidated individually, no implicit repeat count/delay loop. Release and modifier-only/composing/physical-only events are unsupported; unknown event phase is not invented. A frontend that only sees presses may submit presses without claiming repeat/release fidelity. |
| `Paste`, bracketed mode on | At most 8,192 UTF-8 content bytes, repertoire as `CommitText` plus HT/LF/CR; reject other controls, ESC and thus any embedded wrapper delimiter. Explicit policy `lf-from-crlf-v1` changes each CRLF or lone CR to LF, preserving LF/HT; record the policy and resulting bytes in the operation binding. Emit exactly `CSI 200~` + transformed bytes + `CSI 201~`, wrappers excluded from the content cap. Add no Enter. No interleaving within one paste dispatch; a partial write can still leave incomplete wrappers and uncertain application state. |
| `Paste`, bracketed mode off | Default refusal. An explicitly requested policy `unbracketed-single-line-v1` permits repertoire text only (no HT/CR/LF/controls), sending it unchanged without wrappers; otherwise unsupported. No silent bracketed-to-unbracketed fallback. Outer paste wrappers are decoded once into the typed intent, never tunneled; absence of host paste detection stays a visible endpoint limit. |
| `FocusReport`, `?1004h` | Known focus-in/out for the identified admitted view → `CSI I` / `CSI O`. With mode off, reject as unsupported before write. Focus is a hint about this view, never an opaque widget fact or permission. A product focus switch does not silently dispatch a report. Missing outer focus information remains unknown. |
| `Mouse`, enhancements, raw | Mouse is unsupported in N1. Kitty/MOK negotiation, release encoding, alternate enhancement stacks and format/associated-text flags are unadvertised; requests and output setters do not enable them. `SendRaw`, if separately granted, is an exact payload capped at 8,192 bytes through the same writer/receipt path; it is outside the logical-key guarantee and cannot bypass unknown-state refusal. |

RIS/DECSTR reset application cursor/keypad, backarrow, paste and focus as specified in the output table. Buffer switches do **not** reset these session input modes, and no enhancement stack exists in N1. Future Kitty/MOK advertisement requires reviewed exact query/set/unset/push/pop/reset bytes, levels/flags, per-primary/alternate stack ownership and overflow/underflow, legacy fallback/alias policy, format variants, consumed/layout/associated-text handling, and precedence when protocols overlap. [Kitty's specification](https://sw.kovidgoyal.net/kitty/keyboard-protocol/) and S08 MOK practice are different contracts; an `enhanced=true` field or an outer host's negotiation satisfies none of those prerequisites.

## Single reply authority

Only the canonical reducer proposes responses to terminal queries. Reply IDs derive from session incarnation, originating event and ordinal; the broker/keeper owns dispatch receipts. Preserve repeated identical legitimate query replies; never deduplicate by byte content. Renderers and reattached views produce no replies. Historical interpretation replay suppresses all external effects, and a delivery-unknown reply is not resent automatically. Palette/geometry/device responses use the state/profile at the defined cut, never whichever frontend happens to be focused. Host-side TUI capability negotiation uses a separate bounded setup channel and cannot answer inner application queries.
