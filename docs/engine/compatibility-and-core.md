# Compatibility boundary and owned core

[Campaign](index.md) · [Native contract](native-contract.md) · [Recovery](runtime-persistence-security.md) · [Validation matrix](delivery-and-validation.md#compatibility-matrix)

**Proposed design.** No new parser or engine implementation exists. Sources S02–S16/S20–S22 distinguish OS contracts, standards and implementation practice; decisions below define namtab profiles rather than universal terminal behavior.

## Execution boundary

Unmodified interactive programs receive a real PTY slave with controlling-terminal/session setup, sane initial termios, geometry and an honestly advertised terminal profile. The keeper owns the master. The shell/program owns its normal job-control behavior; it can change termios and its foreground process group. Do not run an emulated shell inside the engine or implement libc/system calls. A terminal is neither the shell's grammar nor its filesystem/environment.

The platform path must handle allocation/setup/exec error reporting, close-on-exec FDs, child reaping, nonblocking partial reads/writes, EINTR/EAGAIN and Linux PTY close/EIO behavior. A process/session leader PID alone is not a safe job-control abstraction. Track runner incarnation and stable handles where supported; observe group/foreground relationships with platform APIs. The keeper must not fight an interactive shell's `tcsetpgrp` transitions. PTY EOF, a child exit, shell job completion, stopped jobs and a drained output frontier are distinct facts (S02–S05).

With ordinary fd 0/1/2 attached to one slave, stdout and stderr are **merged terminal bytes**; their original provenance cannot be recovered. Managed pipe execution preserves separately read stdout/stderr, each with offsets, EOF and timestamps. Their combined UI order is the order the runner observed reads, not a total order of original writes across pipes. Pipes change isatty/buffering/line-discipline behavior; never force pipe and PTY fixtures to have identical output. Programs may open `/dev/tty` or retain FDs in descendants; drain/timeout facts must remain explicit.

Native pipe output is raw stream evidence with a safe text/escaped-control projection by default, not implicitly fed into a legacy terminal model. Structured application records are opt-in typed side-channel data. If a program needs terminal behavior, request a PTY at launch; changing a pipe-backed process into a PTY in place is not supported. Initial pipe stdin is explicitly closed or a bounded predeclared authorized byte payload; general streaming stdin can be a separately scoped later operation, not an application-keystroke route.

Ctrl-C sends a key/input byte according to the profile. Kernel VINTR/ISIG/foreground state may turn it into a signal; the program can change or ignore that behavior. `SignalExecution` and runtime termination are separate granted operations. Group signals do not guarantee all descendants or remote effects stop. Resize records a new canonical geometry cut and a separately observed ioctl result; SIGWINCH/repaint is asynchronous (S03–S06).

Shell integration is optional. v1 candidate adapters report prompt/command boundaries and cwd as attributed hints, without trusting OSC 133/title/CWD text as authority. A stronger execution adapter must use an authenticated execution-bound side channel and still report only what it can observe. Basic shells work without hooks, Zsh, a prompt theme or rc modification. Adapter installation/migration is a later explicit workflow, never startup side effect.

## Profiles and negotiation

Profiles are immutable versioned feature manifests, shared by parser, encoder, terminfo, observations and test matrix. Capabilities distinguish **implemented**, **negotiated**, **available at this endpoint**, and **authorized**. A frontend lacking a physical chord does not remove an inner agent capability. An unsupported profile is refused before launch/input; a well-formed unsupported output sequence follows that profile's documented consume/ignore policy and produces bounded diagnostics, not guessed semantics.

## Finite N1 development profile

This section owns the proposed `px-dev-text-0` contract for issue [N0-04 #10](https://github.com/whoodes/namtab/issues/10). N1's target is a clean-rc Bash/readline shell, simple ASCII commands, completion requested with Tab, history/editing keys and live-owner late attachment. That is a **qualification target**, pending real executable/version/locale/terminfo/PTY and both-frontend tests. A JSON expectation or TERM entry cannot prove the shell is useful. No opaque program's widget focus, completion result, command acceptance or readiness is inferred from these bytes/cells.

### Syntax, initial state and errors

Notation: `ESC=1b`, `CSI=1b 5b`, `SS3=1b 4f`, `ST=1b 5c`; spaces between tokens are explanatory, not bytes. Coordinates in this contract are one-based. `n` defaults to 1 when omitted or zero; `r,c` likewise. A supported sequence must match its entire private prefix, parameter arity, intermediates and final byte. A default does not authorize extra parameters. Semicolon-separated empty parameters take that row's defaults; colon subparameters are unsupported throughout N1. Bytes are ordered output data, separate from typed application-input operations.

**P malformed syntax:** ESC collects intermediate bytes `20–2f` then a final `30–7e`; CSI collects parameter bytes `30–3f`, then intermediates `20–2f`, then a final `40–7e`. At most one leading private prefix is allowed; a parameter after an intermediate, repeated/misplaced private prefix, or unsupported subparameter makes the sequence ignored through its final. C0/cancel/restart rules below still apply during ignore. A non-ASCII byte inside ESC/CSI cancels that sequence, discards that byte and records malformed status; following bytes start at ground. Malformed sequence bytes are not printed as text. This bounded private policy awaits the same review as supported syntax, rather than claiming universal ECMA error recovery.

**P, fixed development bounds:** geometry is 2–200 rows by 2–500 columns, no more than 100,000 cells per grid; reject invalid creation/resize before application. CSI permits at most 64 parameter fields, each at most five decimal digits and value 65,535, at most two intermediate bytes and 512 total bytes including introducer/final. Any exceeded bound discards that whole sequence through its final byte; CAN/SUB cancels and ESC starts a new escape. Counts do bounded grid work even if large. Unsupported strings retain no payload, only bounded kind/terminator continuation; discard continues across chunks until its terminator, cancellation or stream EOF. These exact dev choices await NG0 review; broader state/history/resource policy remains [N0-05's inventory](#complete-semantic-state), not a new performance claim.

Initial state: primary grid active; both grids blank with default attributes; cursor `(1,1)`, visible, steady block, no pending wrap; primary history empty; full-height vertical region; origin off; autowrap on; normal cursor keys; numeric keypad; backarrow sends DEL; paste/focus reporting off. Each grid owns its cursor, pending wrap, vertical region, tabs and one save slot. Tabs initially occupy columns 9,17,25,… within width. Attributes and input modes are session state unless the table explicitly saves/restores them. No insert/newline mode, left/right margins, character-set switching, keyboard stack or mouse state is active in this profile.

Input modes otherwise survive. Repeated `h` on alternate is a no-op, not a stack push or clear. First `l` on alternate returns to unchanged primary cells/region/tabs/ordinary save slot and restores the return slot fields with clamping; discards alternate contents and invalidates the return slot. Alternate scrolling adds no primary history. This dedicated-slot policy is a declared choice, not universal xterm behavior. |

| `CSI ! p` / S08 syntax, P action | Exact DECSTR, no parameters: preserve both grids/history/cursors/tabs/save slots and active buffer, clear both pending-wrap flags, reset both regions to full height; default attributes, origin off/autowrap on, visible cursor, normal cursor/numeric keypad, DEL backarrow, focus/paste off. | Unsupported ESC/CSI/string / P | Consume/ignore a well-formed unsupported sequence with saturating diagnostics, no glyph/reply/host action. For N1, primary history is capped at 1,000 physical rows; only full-screen primary upward scroll appends history, evicting oldest rows with explicit range unavailability. Partial-region scroll/erase/alternate output never appends. N1 resize **does not reflow**: preserve the top-left intersection, blank new cells with default attributes, clamp cursors/save slots, clear pending wraps, reset regions to full height, keep in-range tab stops and add no new stops, invalidate the 1049 return slot. Cropped cells are unavailable, not recoverable hidden rows. Logical-line identity and soft-wrap/history-anchor behavior still require N0-05 review; these finite resize rules do not claim the later v1 reflow or complete durable snapshot contract.

### Truthful TERM and terminfo plan

`TERM=px-dev-text-0` names only this private profile. No TERM aliases; no `use=xterm*`, `use=ansi`, `COLORTERM=truecolor`, `Tc`/`RGB`, `colors=256`, copied xterm DA or remote fallback to xterm. Both frontends launch the same inner TERM/profile; the outer TUI's TERM and decoder capabilities are independent. An entry is not yet created/installed. N1 must compile its reviewed source into a project/user-local directory, pass its path explicitly to the child (`TERMINFO`, with inherited search paths reviewed), and refuse full profile launch if the child cannot find the exact entry. No global writes or automatic remote installation. An opaque `ssh` target needs a separately available matching remote entry or an explicitly different qualified profile.

The following is the **entire proposed terminfo allowlist**, using S09 names. Parameter placeholders below describe emitted bytes, not a tested `tic` source. Missing capabilities stay absent; do not inherit an entry's extras. Numeric `cols/lines` describe the launch tuple (PTY size remains separately observable); publish a generated exact launch entry or verify the chosen library's resize handling before certification.

## Parser and deterministic application

Recommended starting point: a small owned incremental byte FSM, with a reviewed transition table and semantic dispatch table. Reuse standards techniques, checked UTF-8/Unicode primitives and test generators. Do not import an existing emulator's screen/modes as the authority. vte action dispatch is a useful comparator, but its private continuation makes direct reuse conditional; a maintained lexer dependency is eligible only with a public complete bounded state representation and compatible licensing. No lexer fork or dependency is created in this campaign.

```text
ordered keeper output/resize/control events
    → owned incremental lexer + UTF-8 continuation
    → profile-specific semantic reducer
    → canonical state + immutable observation changes + proposed effects
    → broker fences / keeper delivery (effects), subscribers (observations)
```

One session owner applies an explicitly ordered sequence. Pure reduction is deterministic **only for fixed event order, profile/data versions, initial state and specified limit/error policy**. Clock reads, randomness, OS calls and direct callbacks do not occur inside it. Scheduling, application execution, interleaving of external processes and model behavior are not deterministic replay claims.

That equivalence concerns successful bounded reductions with available resources. It does not promise identical allocation failures, scheduling or OOM behavior across machines. A classified resource failure must refuse/latch the relevant state rather than invent a successful next frame.

The FSM represents ground, escape/intermediates, CSI entry/parameters/intermediates/ignore, OSC/string payload and terminator handling, DCS/APC/PM/SOS consumption, UTF-8 continuation and cancellation/error states. Own pending ESC in a string terminator, partially accumulated numeric/subparameters, UTF-8 prefixes and parser ignore/discard state. Recognize bytes in the right parser context; do not decode a UTF-8 codepoint and re-run its value as an escape control. v1 chooses UTF-8 plus supported 7-bit control forms; legacy 8-bit encodings are a separate profile. CAN/SUB, ESC inside sequences, invalid UTF-8, unexpected final bytes and EOF have explicit testable rules, not ad hoc recovery at chunk boundaries.

Caps cover geometry/cell counts, parameter/subparameter counts and arithmetic, string payload, grapheme bytes, history, mode stacks, effect/reply size and diagnostics. Initial safety-cap candidates for N0 are 64 CSI parameter entries, 16 KiB retained string payload, 256 bytes per retained grapheme and a 16-entry keyboard stack; these are **proposed tunables**, not measured sufficiency or new performance SLOs. Final limits and exact overflow policy become part of the profile before advertisement. Saturating diagnostic counters must not become unbounded logs.

Counted operations such as repeat, scroll and insert must do work bounded by affected grid/history limits, not loop an attacker-supplied integer billions of times. Parsing limits alone do not establish a CPU bound. Snapshot import likewise validates structure/lengths before allocating declared collections, with a bounded serialized input and no decompression in v1.

Oversized strings enter a bounded discard-until-terminator state, retaining only what future parsing needs. This is not arbitrary loss of canonical input: every byte still drives the defined state machine. Unsupported graphics/file protocols are consumed without decoding images or host actions. Malformed/unsupported input under a specified policy is not automatically “unknown”; unknown is required for missing parser bytes, failed state invariants or unclassified partial application. No guessed resynchronization makes an opaque TUI correct after an actual stream gap.

## Complete semantic state

This is the v1 inventory. A profile owns only its admitted features, with explicit absent/default values for exclusions; the finite N1 table excludes character-set switching, wide/grapheme state, mouse and keyboard enhancement stacks. N0-05 must reconcile the exact bounded representation, including N1's dedicated 1049 return slot and live late-attach state. This table does not add those excluded features to N1 or claim a snapshot implementation.

| State family | Required ownership / continuation obligations |
| --- | --- |
| Buffers and history | Primary and alternate grids; active buffer; stable logical-line IDs, soft-wrap markers, bounded primary history and viewport anchors. Alternate content is not flattened into a command log. |
| Cursor and saved state | Cursor, wrap-pending, visibility/style; each supported save/restore slot with associated attributes/charset/origin state specified by the profile. Saved cursor alone is insufficient. |
| Editing geometry | Rows/columns; top/bottom and supported left/right margins; origin/insert/autowrap/newline modes; tab-stop set; scroll/erase/insert/delete rules and blank-cell attributes. |
| Attributes and character sets | Foreground/background/default/index/RGB distinctions, palette and supported decorations; G0/G1 DEC line drawing and shift state for the initial text profile. |
| Protocol modes | Application cursor/keypad, numlock policy, backarrow, focus/paste/mouse, synchronized output, keyboard negotiation and **separate primary/alternate Kitty stacks**, resets and query state. |
| Text | Incremental UTF-8, Unicode/profile versions, grapheme continuation, lead/trailing wide cells and stable text-to-cell mapping. No dependency-private iterator or shaping pointer in snapshots. |
| Extensions and errors | Bounded supported hints/hyperlinks, sanitized title metadata, unsupported/discard states and diagnostic/loss flags. No host authority in extension payloads. |

A reducer transaction either commits a valid next state/frontier and its effects or latches unknown without exporting a fabricated partial frame. Large byte events are reduced in bounded quanta; no observer sees half a committed semantic mutation. A background snapshot may use a bounded immutable/COW view, but cannot make an unbounded stop-the-world copy an interaction requirement.

## Unicode, reflow and rendering boundary

For v1, recommend versioned Unicode 18.0.0 data and approved UAX #29/#11 references from S11–S13, with bootstrap hash/license checks and a matching implementation primitive. N1 remains the finite repertoire above. Width is an owned profile: ambiguous width defaults narrow, emoji/variation/ZWJ and combining behavior are explicitly table-driven/tested, not inferred from font metrics. No normalization changes application bytes. Invalid UTF-8 has a specified replacement/diagnostic policy and optional authorized raw evidence. Unknown/private-use/unassigned glyph width needs a fixed profile fallback.

Keep stream byte offsets, Unicode scalars, grapheme clusters, logical lines, terminal cells and glyph positions distinct. A cluster may grow across writes; a later variation selector can require a bounded correction to the lead/trailing cells, cursor and delta revision. Editing part of a wide cell clears/repairs the entire occupancy according to a fixture. Leading combining marks and right-edge width changes need hand-authored cases. Reflow cannot rewrite original byte citations.

For v1, primary-buffer soft-wrapped logical lines reflow on resize under the published policy; N1 uses the explicit crop/no-reflow policy above. Hard breaks and alternate-screen content do not magically become reflowable prose. Map history/selection anchors or invalidate them explicitly; cap shrink/expansion work. Resizing and subsequent application repaint are separate events. v1 terminal cells use logical order without full bidi reordering; expose that limitation, safe bidi markers in review chrome, and readable logical inspection. Full bidirectional terminal editing requires a later profile and mapping tests, not an assertion that Unicode storage implies bidi support.

Shaping, font fallback, ligatures and rasterization are presentation concerns constrained by canonical occupancy. They cannot change agent cell positions. Electron and the outer TUI host may paint differently; that is a visible capability/quality issue, not permission for two width authorities.

## Input policy

Keep three planes: namtab UI commands, application input intents, and native automation/control operations. Keyboard packets distinguish named logical key; text/layout facts; optional physical code; modifiers and **consumed** modifiers; composing state; press/repeat/release; endpoint capabilities. Unknown facts stay absent. `CommitText` represents an IME/text commit, not a loop inventing physical key presses; its treatment under report-all/associated-text modes must have a documented encoder contract before that combination is advertised.

The required inner set covers arrows, Tab/Shift-Tab, Enter/Escape, Home/End/PageUp/PageDown/Insert/Delete/Backspace, F1–F12, keypad identities and advertised Ctrl/Alt/Shift chords. A structured key conveys intent and one encoding authority; raw bytes convey an exact authorized payload but require the caller to know its profile. Neither supplies opaque application meaning. Unsupported modifiers, event phases or encodings are refused before writing, without silent raw fallback. `Tab` asks the application to handle Tab; the engine does not run a universal completer. Text preserves declared characters without normalization; ordinary text fields cannot hide C0 controls. Raw application bytes go toward the program, never into the output parser.

The owned encoder reads canonical typed modes directly. Ordinary legacy policy includes Ctrl-I/M/[ → `09/0d/1b`, real Tab/Enter/Escape and documented Alt/Shift/Ctrl behavior. Enhanced Kitty/MOK preserves distinctions after explicit negotiation; no unnegotiated fixterms default. Cover cursor/keypad modes, numlock/backarrow, function keys, consumed Shift/AltGraph/layout facts, per-buffer mode stacks, reset and protocol precedence. N0 must resolve the detailed MOK format/level table before v1; unsupported combinations return a typed capability error before writing, not guessed bytes. Native agents can supply explicit logical keys that the host cannot physically report.

Mouse coordinates bind to geometry/buffer/revision and negotiated tracking/encoding; selection in namtab is distinct from editor selection via keys/mouse. Focus events are protocol hints tied to view identity, not permission. Paste is a separate typed bounded operation: wrapper policy reads **inner** mode, dangerous controls/delimiter injection and newline transformation are explicit, never append Enter automatically. Outer TUI paste wrappers are decoded once, not tunneled inward. Legacy Escape can be a lone key or an Alt/sequence prefix; transport fragmentation and application timeouts preserve ambiguity even after one local write. Outer decoding reports only facts it knows. Enhanced release/repeat distinctions require end-to-end negotiated support; bounded repeated presses remain separate non-idempotent events. Do not infer certainty from sleeps or invent key-up events.

Ordinary paste rejects embedded controls/delimiters unless a separately explicit policy permits them; unbracketed fallback requires declared policy rather than silently pretending equivalence. Record every newline/control transformation in the operation identity. Partial paste can leave incomplete wrappers and uncertain application state. Bracketed paste is not an execution-safety guarantee.

`SendRaw` is a granted bounded compatibility fallback through the same writer/freshness/receipt path. It may have effects the logical encoder cannot describe and must say so; it does not repair a missing canonical state, bypass protected prompts or promise safe retry. An engine in unknown state refuses all application-input routes. Separately authorized OS controls remain possible.

### Finite N1 input table

This table narrows the general v1 policy above for `px-dev-text-0`; it is the same **accepted-for-drafting recommendation** as the output table. It specifies inner encoding after broker admission/freshness/authority checks, not a new public wire schema. [S08](https://invisible-island.net/xterm/ctlseqs/ctlseqs.html) documents several configurable keyboard conventions; the choices below are **P**, not a promise to reproduce every xterm configuration. Bytes shown are complete payloads, with no trailing Enter/newline. Unsupported combinations fail with the existing typed `UnsupportedCapability` error family **before writing any bytes**; do not drop a modifier, synthesize a layout, fall back to raw or split a rejected operation. Invalid UTF-8, forbidden controls and contradictory facts use `InvalidRequest`; a valid out-of-repertoire scalar uses `UnsupportedCapability`; exceeding a byte/event cap uses `ResourceExhausted`. Concrete wire spellings remain N0-06 work.

Both desktop and host TUI submit the same canonical logical-key/text/paste intents and read the same inner modes. The [outer TUI decoder](../ux/13-dual-frontend-and-host-tui.md#input-modes-and-nesting) can only supply facts that survive its host/SSH/multiplexer. An ambiguous outer `09` establishes neither a physical Ctrl-I nor a physical Tab; its conservative logical Tab intent has the same classic bytes. Send key/native callers can request either explicit intent. Unknown physical/layout/NumLock/consumed/release facts remain absent. A key palette improves representability; it does not establish application focus or meaning.

| Canonical input / conditions | Exact N1 bytes / refusal |
| --- | --- |
| `CommitText` | UTF-8 for text within the output repertoire (ASCII printable and U+00A0–U+00FF except U+00AD), unchanged, at most 8,192 bytes per operation. Reject any other scalar or C0/DEL/C1; no hidden control in a text field. IME commit is sent once, without synthetic key presses. Preedit is local presentation state; no report-all/associated-text mode exists. |
| Character `SendKey`, no remaining modifiers | Exactly one explicitly supplied logical/layout-resolved repertoire scalar, encoded as UTF-8. A native caller can state that character directly; a frontend cannot derive it from a physical code alone. Consumed Shift/AltGraph facts may explain the supplied text but do not add bytes. Bulk/IME text uses `CommitText`; missing/contradictory character facts are rejected. |
| Named `Tab`, `Enter`, `Escape`, no modifiers | `09`, `0d`, `1b` respectively. The program handles completion, newline or escape. `Enter` does not mean LF and does not prove command execution. |
| Classic Ctrl aliases | Ctrl+A–Z (case-insensitive logical letters) → `01–1a`; Ctrl+Space or Ctrl+@ → `00`; Ctrl+[ / Ctrl+backslash / Ctrl+] / Ctrl+^ / Ctrl+_ → `1b/1c/1d/1e/1f`; Ctrl+? → `7f`. Thus **Ctrl-I=Tab=09, Ctrl-M=Enter=0d, Ctrl-[=Escape=1b** on the wire, while intents/receipts preserve their requested identity. Ctrl+C is `03`; termios/foreground state, not the encoder, decides signal behavior. Other Ctrl+character combinations are unsupported. |
| Shift on character/control intents | Printable characters come from committed/layout-resolved text; Shift that was consumed producing that text is not applied twice. For a control chord, Shift is accepted only if endpoint-supplied consumed facts remove it (e.g. the Shift needed for a known `^`); remaining Shift+Ctrl+character is unsupported. No assumed US physical-key map, AltGraph=Ctrl+Alt guess, CapsLock rewrite or physical-code-only event. |
| Named `Backspace`, no modifiers | `7f` normally; `08` while `?67h`. This is distinct from Ctrl+H, which is always `08`. `Delete` is the separate named editing key below. |
| `Up/Down/Right/Left`, `Home/End`, no modifiers | Normal cursor mode: `CSI A/B/C/D`, `CSI H/F`; application mode (`?1h`): `SS3 A/B/C/D`, `SS3 H/F`. Keypad mode does not change these keys. |
| `Insert/Delete/PageUp/PageDown`, no modifiers | `CSI 2~/3~/5~/6~`, independent of cursor/keypad mode. |
| `F1/F2/F3/F4`, no modifiers | `SS3 P/Q/R/S`. F5–F12 → `CSI 15~/17~/18~/19~/20~/21~/23~/24~` in order, independent of cursor/keypad mode. No F13+ aliases. |
| Shift+Tab | Exactly `CSI Z`. Ctrl+Tab, Alt+Tab, Shift+Enter/Escape/Backspace and other modified Tab/Enter/Escape/Backspace are unsupported. |
| Modified arrows/Home/End/F1–F4 | For any nonempty subset of Shift/Alt/Ctrl, `m=1+Shift+2*Alt+4*Ctrl` (2–8). Emit `CSI 1;m final`, where final is A/B/C/D/H/F/P/Q/R/S from the unmodified key. Use CSI in **both** cursor modes; e.g. Ctrl+Left → `CSI 1;5D`, Alt+Up → `CSI 1;3A`, Shift+F3 → `CSI 1;2R`. Do not add a second ESC for Alt. These collide with other terminal traffic; no universal key-origin proof. |
| Modified Insert/Delete/PageUp/PageDown/F5–F12 | Same modifier subsets and `m`; emit `CSI number;m~` using the unmodified number. E.g. Shift+Delete → `CSI 3;2~`, Ctrl+Alt+F5 → `CSI 15;7~`. No Super/Meta/Hyper or extra modifier bits. |
| Alt+character or Alt+supported Ctrl+character | Prefix one `ESC` to the otherwise supported single character/control payload, with no high-bit Meta form. Alt+resolved `x` → `1b 78`; Alt+Ctrl+C → `1b 03`. Character must be one scalar in the repertoire, with Shift already consumed if applicable. Do not apply this rule to named keys, keypad or `CommitText`/IME strings. A lone Escape and an Alt prefix remain ambiguous to a legacy application even after one local write. |
| Explicit keypad `KP0`–`KP9`, `KPDecimal`, `KPDivide`, `KPMultiply`, `KPSubtract`, `KPAdd`, `KPComma`, `KPEqual`, `KPEnter`, `KPTab`, `KPSpace` | Numeric mode: ASCII `0`–`9`, `.`, `/`, `*`, `-`, `+`, `,`, `=`, `0d`, `09`, `20`. Application mode (`ESC =`): `SS3 p`–`SS3 y`, then `SS3 n/o/j/m/k/l/X/M/I/SPACE` in the same order. This selects the distinct VT220-style keypad convention, not xterm's PC navigation-keypad convention. No keypad modifiers; `KPPF1`–`KPPF4` explicitly alias F1–F4. |
| NumLock / keypad identities | NumLock is not an inner modifier or toggle operation; the inner explicit KP identity follows canonical numeric/application mode regardless of host NumLock. A frontend that knows only the host-resolved `Home` or text `1` sends that fact, without inventing `KP1`. Missing keypad identity cannot be recovered. No `?1035`, `?66` or hardware LED policy. |
| Press/repeat/release | Press emits its payload once. A known repeat event emits the same bytes once and receives its own non-idempotent operation identity; it is not a distinguishable legacy repeat packet. Maximum 64 explicit events per admitted batch, revalidated individually, no implicit repeat count/delay loop. Release and modifier-only/composing/physical-only events are unsupported; unknown event phase is not invented. A frontend that only sees presses may submit presses without claiming repeat/release fidelity. |
| `Paste`, bracketed mode on | At most 8,192 UTF-8 content bytes, repertoire as `CommitText` plus HT/LF/CR; reject other controls, ESC and thus any embedded wrapper delimiter. Explicit policy `lf-from-crlf-v1` changes each CRLF or lone CR to LF, preserving LF/HT; record the policy and resulting bytes in the operation binding. Emit exactly `CSI 200~` + transformed bytes + `CSI 201~`, wrappers excluded from the content cap. Add no Enter. No interleaving within one paste dispatch; a partial write can still leave incomplete wrappers and uncertain application state. |
| `Paste`, bracketed mode off | Default refusal. An explicitly requested policy `unbracketed-single-line-v1` permits repertoire text only (no HT/CR/LF/controls), sending it unchanged without wrappers; otherwise unsupported. No silent bracketed-to-unbracketed fallback. Outer paste wrappers are decoded once into the typed intent, never tunneled; absence of host paste detection stays a visible endpoint limit. |
| `FocusReport`, `?1004h` | Known focus-in/out for the identified admitted view → `CSI I` / `CSI O`. With mode off, reject as unsupported before write. Focus is a hint about this view, never an opaque widget fact or permission. A product focus switch does not silently dispatch a report. Missing outer focus information remains unknown. |
| `Mouse`, enhancements, raw | Mouse is unsupported in N1. Kitty/MOK negotiation, release encoding, alternate enhancement stacks and format/associated-text flags are unadvertised; requests and output setters do not enable them. `SendRaw`, if separately granted, is an exact payload capped at 8,192 bytes through the same writer/receipt path; it is outside the logical-key guarantee and cannot bypass unknown-state refusal. |

RIS/DECSTR reset application cursor/keypad, backarrow, paste and focus as specified in the output table. Buffer switches do **not** reset these session input modes, and no enhancement stack exists in N1. Future Kitty/MOK advertisement requires reviewed exact query/set/unset/push/pop/reset bytes, levels/flags, per-primary/alternate stack ownership and overflow/underflow, legacy fallback/alias policy, format variants, consumed/layout/associated-text handling, and precedence when protocols overlap. [Kitty's specification](https://sw.kovidgoyal.net/kitty/keyboard-protocol/) and S08 MOK practice are different contracts; an `enhanced=true` field or an outer host's negotiation satisfies none of those prerequisites.

## Single reply authority

Only the canonical reducer proposes responses to terminal queries. Reply IDs derive from session incarnation, originating event and ordinal; the broker/keeper owns dispatch receipts. Preserve repeated identical legitimate query replies; never deduplicate by byte content. Renderers and reattached views produce no replies. Historical interpretation replay suppresses all external effects, and a delivery-unknown reply is not resent automatically. Palette/geometry/device responses use the state/profile at the defined cut, never whichever frontend happens to be focused. Host-side TUI capability negotiation uses a separate bounded setup channel and cannot answer inner application queries.
