## Current harness presentation boundary

The selected interface and agent adapters consume one authorized model. Keep per-session state/input/reply authority in the owned core/broker boundary, ephemeral focus/selection in presentation, explicit action receipts, revision-bound evidence and gaps/unknowns. No UI or adapter opens private storage or managed PTYs. Proposed subscriptions/deltas/condition waits require H0 contracts and H1 validation before replacing MK1 snapshots. Keep critical human keyboard, actual accessibility, input-to-paint and takeover evidence in the eventual emulator gate. A standalone window, a GPU renderer and an exact client count remain decisions, not assumptions.

## One model, two useful clients

**Historical paired-client formulation:** retain the anchor and reusable semantics; E5 removes the requirement to deliver both.

Admitted clients consume public service projections: revisioned frames/history pages, native process/stream facts, tasks, receipts and authorized artifacts. No inner parser, independent mode tracker, private persistence/worker endpoint or managed PTY access. Disposable glyph/row caches, scroll position, selection and focus are presentation state; rebuilding them cannot alter canonical facts or send replies.

The experimental `FrameStamp` pins session/incarnation, observation/semantic revisions, processed/source frontiers, geometry, active buffer generation and engine/profile/text/reflow/mode/capability revisions. Physical row IDs and row revisions follow the selected dev profile; broader logical-line/grapheme support is not advertised by the shape alone. Deltas apply only to their exact base; a missing base returns resync rather than client-side repair. Large observations/history are paged and credit-bounded. The [N0-06 experimental public seam](native-contract.md#n0-06-experimental-public-projections-and-intents) now owns Rust DTOs, generated schemas/types and synthetic shape cases; product semantics and limits remain proposed. Do not copy private core structs into public bindings.

The type-only `@project-x/protocol/experimental-native-n0` subpath exposes this new public namespace/version to native agents, TUI and Electron. `/view` exposes separate local UI commands. Historical public-v1 and EA1/internal worker APIs remain separate. No current frontend is migrated by these DTOs. Neither client imports worker/private persistence state or handles managed PTY bytes.

Each subscribing client first matches `subscription_opened` to the connection's pending read correlation, obtaining the service subscription ID and resolved selection before any data. This control response, or a correlated initial `subscribe_refused`, remains available at zero presentation credit; an opened zero-credit stream can therefore be granted credit or canceled. Concurrent identical selections keep distinct correlations/stream IDs. Later `observation_unavailable` names its active stream, while stale responses from a disconnected connection cannot satisfy new pending requests. These are proposed routing rules with static shape/example tests; no subscriber or connection state machine is implemented.

Each subscribing client assembles active-grid snapshot pages at one immutable stamp before claiming a full presentation, then apply each complete active-grid delta only to the exact held base. Geometry/buffer/policy changes, lost pages/deltas or expired cursors require resnapshot. History selection is a finite identified range with explicit completeness/capture gaps; clipping a retained physical row does not reinterpret its canonical width. Cursor/row indexes in the public DTO are zero-based. Page and byte credit bound presentation traffic and retained versions; cancellation/disconnect release the read stream without stopping work or restoring input authority. A canonical event gap stays unknown even after a new presentation. The public owner above defines charging, closure and invalid assembly; the clients cannot repair those rules locally.

“Raw terminal view” means ordinary canonical presentation through admitted input, not unmanaged PTY passthrough. [Zero-agent UX and four lenses](../ux/11-human-experience-spec.md#information-architecture-and-default-layout) remain the product entrypoint. The old N1 paired-client plan needed a useful selector, viewport, receipt/status and takeover; E5 replaces that gate. Full Work/Review/search and any window features need explicit selection and qualification, not pane creation per agent.

## Input, focus and command routing

The [native contract](native-contract.md#observeactobserve-races-and-human-override) owns explicit targets, lease/freshness fences and receipts; [core input policy](compatibility-and-core.md#input-policy) owns encoding. Human [desktop keys/focus](../ux/11-human-experience-spec.md#three-action-planes-and-keyboard-behavior) and [TUI prefix/outer decoding](../ux/13-dual-frontend-and-host-tui.md#input-modes-and-nesting) normalize only facts their endpoint knows. UI commands, application intents and automation/control remain distinct. Focus never grants a writer lease.

In the proposed native path, a quoted TUI Ctrl+G must become a control-key intent, not C0 hidden in `CommitText`. The retained public-v1 synthetic fixture cannot represent that key and refuses double-prefix quoting; its palette chord rejects extra Ctrl/Alt/Meta modifiers. Separately, delivered MK1 supports literal Ctrl-G quoting and input pause/re-arm in its experimental path (see the quickstart). Neither proves the proposed generated native SDK or a complete Send key UI. The historical text/paste adapter bounds payloads to 8192 UTF-8 bytes, with bracketed-paste wrappers counted separately; that is not the future native profile's admission policy. Send key can express an inner supported intent when a host cannot physically distinguish it. No client may guess missing layout/consumed-modifier/IME/release facts to claim parity. [DF02/DF03](../engineering/16-test-and-ci-strategy.md#dual-frontend-contract-cases) tests endpoint races and nesting.

The initial public application subset is `send_key`, `commit_text`, `paste` and `focus_report`, with the same exact issued request key, observation/profile and endpoint/writer/protection/deadline checks for human and agent routes. View-derived input additionally binds mapping/focus; direct session input never steals focus. The schema represents a requested key action separately from optional endpoint phase/logical/physical/layout/consumed/composing facts. Unknown facts stay absent; false is known false. Neither a key palette nor a legacy alias establishes physical facts or opaque application-widget focus.

`tests/fixtures/native-public/intent-cases.json` has shared TUI/Electron shape variants for explicit Ctrl-I/M/[ versus named Tab/Enter/Escape, host double Ctrl-G versus desktop Send key, text commits, paste/focus modes, wrong focus and stale observations. UI `select_view`/`open_palette` are rejected as application intents. The matrix labels encoded bytes and semantic refusal expectations as **unexecuted review requirements**; current schema tests prove only shape acceptance/refusal. They do not test a host prefix decoder, either frontend, an encoder, freshness, byte quotas or dispatch. DF01–DF04/V10/V16 still require independently reviewed executable both-client oracles and real implementation.

## Text, rendering, selection and accessibility

**Historical renderer recommendation, superseded by E5: virtualized DOM cells/runs with explicit grid geometry**, browser shaping/font fallback and an accessible reading projection. No browser emulator. Prove occupancy, cursor, selection and actual assistive interaction before optimizing. Canvas/WebGL is a later measured replacement for painting only if DOM limits justify it and the same semantic accessibility/selection contract survives. Do not build two renderers in advance or assume a DOM node per cell meets G6.

Canonical widths/cluster occupancy come from the [core text profile](compatibility-and-core.md#unicode-reflow-and-rendering-boundary); fonts/shaping may not reinterpret them. Selection anchors bind session/buffer/logical-line/column and revision, with explicit mapping or invalidation after erase/reflow/eviction. Copy/search cite authorized ranges and gaps; an application selection is separate from a view selection. [Human rendering/paste/search](../ux/11-human-experience-spec.md#rendering-selection-paste-and-scrollback) owns font/theme/clipboard/preview behavior, and [host capabilities](../ux/13-dual-frontend-and-host-tui.md#paste-resize-and-terminal-capabilities) owns outer width/color/paste limits.

IME preedit stays frontend-local; committed text goes once through the typed path. Candidate placement tracks canonical cursor/viewport. Desktop accessibility maps semantic controls/reading ranges to those facts; full-screen TUI cells cannot invent a native accessibility tree. Critical workflows need actual [accessibility tests](../ux/11-human-experience-spec.md#accessibility-and-performance-behavior), not only ARIA, headless grids or a linear log.

## Native-to-legacy journeys

**NJ1: native agent work, then human debugging.** Agent starts task T/attempt A, runs an argv test command with pipes, watches separate streams and an exact execution ID, and registers authorized artifact revision R. Human receives one Review item, inspects exit/drain facts and artifact diff, then opens a **new** PTY editor session at that context. A pipe-backed process cannot simply be converted into a terminal-attached process. Validation of R becomes stale if the editor changes it; task acceptance requires a new bound result. The [NG1 gate](delivery-and-validation.md#ordered-milestones) uses only the explicitly bounded pipe/artifact/shell/takeover/live-reconnect subset: full editor handoff requires the declared N2 application profile, and richer Review/diff/search presentation follows N3. A minimal N1 artifact/status view must still distinguish R from a later revision; this staging does not waive that provenance requirement.

The shared journey catalog is [J01–J09](../ux/11-human-experience-spec.md#end-to-end-journeys-and-transition-evidence): zero-agent shell (J01), delegation/review (J02/J03), stale approval (J04), takeover (J05), reconnect versus engine loss (J06), sensitive/remote interaction (J07), config migration (J08), cross-client handoff (J09). NJ1 above adds the native-pipe boundary; it does not duplicate that catalog. Observe–act–observe and N01–N16 govern opaque navigation throughout.
