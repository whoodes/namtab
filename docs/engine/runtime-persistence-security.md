## Module and process design

Preserve the **seven Rust/four TS workspace packages**, historical source and original X4/EA1 failures. The active-source CI lane covers six Rust crates and excludes the historical `project-x-engine` from its Clippy/tests; that exclusion does not remove its workspace membership or change the seven-package import check. The next separately authorized implementation should add **one** cohesive owned package, provisionally `crates/terminal`, containing a pure library and `project-x-terminal-worker` binary. Do not repurpose/delete `crates/engine`, reinterpret its DTOs or retire its manual gates. No lexer/width/checkpoint/wrapper microcrates, plugin ABI or service per method.

| Boundary | Proposed responsibility / imports | Authority and failure limit |
| --- | --- | --- |
| `domain` | Pure work/evidence/lease/approval transitions; independent of `protocol`. Extend existing models after reconciling semantics. | No terminal parser, OS, database, GUI, real clock or implicit policy side effects. |
| `protocol` | Leaf public/private wire types, version identifiers, bounds and schema export. Large IDs are bounded decimal strings. | No policy evaluation, semantic terminal state, grant creation or executable callbacks. A generated DTO or opaque authority reference is data, not an admission decision. |
| `terminal` library | Pure terminal semantics, owned state and semantic versions; reviewed algorithm/serialization primitives only. | No `protocol`, OS handles/calls, clock, randomness, network, storage, GUI, grant evaluation or direct output callbacks. |
| `terminal` worker binary | Private transport, one serial core owner per session, scheduling and DTO↔core conversion. Imports `protocol` and its library. | No public listener, PTY ownership/write route, receipt/admission database or grant creation; a fault can lose every mapped session. |
| `platform` and keeper | OS process/PTY/pipe/worktree/runtime adapters and stable-handle observations. `platform` may import `domain`. Keeper owns master FDs, delivery facts and controller fencing. | No terminal interpretation, public admission or UI policy. Child process status and stream drain remain separate. |
| `service` | Sole public authentication/authority boundary: domain policy, admission/receipt store, evidence coordination, worker/keeper orchestration and subscriptions. Imports `domain`, `platform`, `protocol`. | Rechecks authority; never trusts a worker result as a grant or instantiates a second terminal interpreter. |
| `client` / `console` / desktop + TS protocol | Authorized public IPC, read caches, intent and presentation. `console` → `client` → `protocol`; desktop → TS protocol. | No private DTO/endpoint, store/evidence path, PTY FD or core import. Neither frontend maintains authoritative terminal modes or generates application replies. |

The intended compile graph stays acyclic. Runtime service↔worker messages do not justify a compile dependency from the pure library back to `protocol`/service. Within the future library, keep value types as leaves; `text`/`lexer`, `screen` and `modes` implement bounded state operations; `input` consumes an immutable canonical mode view; `reduce` owns ordered state transitions; `snapshot` and `observe` consume committed state. The public library facade exposes initialization, bounded ordered-event reduction, canonical input encoding and immutable projections, using owned typed values. Exact Rust signatures remain implementation work. Snapshot decoding may validate semantic state but cannot create an OS/resource handle. A worker translates wire enums/IDs/checked integers into those values and maps typed outcomes back; it does not mirror mode flags in a second mutable model. Public projections are derived from the same committed core cut.

Start with safe Rust and reviewed safe OS wrappers. The new pure library forbids unsafe across all its modules/features, including test helpers; the worker's ordinary transport/mapping code uses safe APIs. Unavoidable launch/PTY syscalls belong in a narrow `platform` seam, or separately reviewed font FFI outside terminal semantics, with documented FD ownership, lifetimes, allocator/thread affinity and unwind invariants. Existing EA1's audited `ffi.rs` exception stays historical, not a precedent for new unsafe core code. Reject transmuted snapshots, callback pointers, private native-emulator ABIs and dynamic in-process plugins. [N0-08 selection](../engineering/15-dependencies-and-supply-chain.md#n0-primitive-and-data-selection-2026-10-16) owns proposed primitives/data; dependency, project-license and implementation admission remain separate.

### Worker ownership and failure domain

N1's proposed topology is one dedicated owned worker multiplexing a **bounded admitted session set**, with one serial reducer owner per session. Service owns the session→worker/incarnation assignment. A reducer yield preserves private staged progress and cannot publish a partly reduced frame; the [core work limits](compatibility-and-core.md#resource-limits-and-failure-policy) govern event/quantum accounting. One worker is a deliberate shared failure domain, not one process/thread per agent. A bounded pool needs later measured fault/resource justification.

| Condition | Required boundary behavior |
| --- | --- |
| Invalid private request before reduction | Reject without state mutation using the existing typed error family; preserve the last committed cut. Repeated malformed frames can close that connection under its bounded policy. |
| Broken invariant, unclassified partial mutation or lost canonical bytes for one session | Latch that session's interpretation unknown, discard unpublished candidates, notify service and fence all its application-input routes. An apparently plausible screen cannot clear it. |
| Worker crash, OOM, transport loss or unresponsive worker | Service marks all assigned interpretations unavailable/unknown, retires the worker incarnation, refuses new dependent admission and requests keeper fences for input/replies. A fence is confirmed only at its keeper acknowledgment; queued/in-flight effects retain exact-prefix/unknown receipts, including when the keeper is unreachable. Preserve independent process/pipe/receipt facts. A watchdog timeout observes unresponsiveness, not proof of death or rollback. |
| Old worker reconnects or sends a late result | Reject the retired worker/controller/session binding; no late frame, reply proposal or cancellation result can become current. A replacement worker starts with a new identity. |
| Parser/snapshot/search stalled while human revokes or stops an execution | Service→keeper controls have a reserved route independent of worker progress. Report fencing/termination observations and any unreachable keeper; never wait for a terminal parser acknowledgment to admit emergency control. |

Service/keeper asynchronous I/O may use the separately selected runtime; CPU parsing, snapshot encoding, search, hashing and font work must not block their control loop. A worker task panic is not a recoverable partial state merely because it was caught: only a demonstrated unchanged committed state or validated exact-cut restore permits continued reduction. Process limits and restart backoff must bound restart/failure storms; they do not establish a sandbox or a measured response time.

## Ordering, fairness and budgets

The keeper sequences observed PTY output, acknowledged geometry operations and delivery records. The engine consumes events in that order. Cross-process readiness is not an atomic picture of the application; record requested/applied cuts and uncertainty. Native pipe streams retain independent offsets and service observation order. Engine replies and authorized application input have distinct identities but one explicitly ordered final write queue, with no byte-level interleaving of partially delivered operations. The worker proposes bytes/effects with originating event/operation identity; only the service/keeper path can admit and deliver them under the [writer/receipt contract](native-contract.md#minimal-operations-and-asynchronous-outcomes).

Use bounded per-session/per-principal/global input, output, effect, observation and evidence budgets. Service admission reserves capacity before assigning work; queue capacity is not an authority grant. A worker schedules ready sessions round-robin with charged core work quanta and bounded per-session queues; no session gets a second quantum while another ready session is continuously bypassed. Account for scans/copies, query/control floods, serialization and staged mutations as well as byte consumption. Human input, takeover/revoke and failure controls have reserved queue capacity, with emergency service→keeper controls outside the worker. Priority cannot let old-mode input overtake earlier canonical output, reorder a partial final write, or revoke delivered effects. Cancellation of obsolete observation/search/snapshot work releases its credits at a safe boundary; it cannot roll back committed reduction or a delivered operation.

Coalesce render deltas and cancel obsolete search/index/snapshot work; never coalesce away parser bytes or committed control events. Slow readers get the public contract's explicit resync/disconnect outcome rather than unlimited state copies. Backpressure can block the program and change timing. If a capture sink fails while parsing continues, capture becomes gapped; if canonical input is actually missing, interpretation becomes unknown. Full storage refuses new evidence reservations before execution or explicitly records degraded policy under the existing grant; it never silently evicts pinned evidence. Even exhausted control storage cannot make emergency revocation wait for an audit write; disclose the persistence failure under the [storage contract](../architecture/05-architecture-storage-and-extensions.md#storage-and-durability).

[G6](../engineering/07-validation-roadmap-and-risks.md#performance-and-resource-budgets) owns product workload/latency/memory allocations. N1 measures a smaller declared workload; N3 qualifies the full reference without counting independent caps as simultaneous guaranteed capacity. [Product resource admission](../engineering/07-validation-roadmap-and-risks.md#resource-scheduling-and-overload) separately accounts attempts, parent/provider limits and human attention. Before implementation admission, review one finite runtime tuple covering concurrent sessions, per-session/total resident state and staged/snapshot copies, transport/queue bytes, reserved controls, CPU quanta/watchdog and restart policy. Core development bounds and the transport review limits below are inputs to that tuple, not owner-approved admission or achieved G6 results.

## IPC, configuration and extension scope

Use length-framed, bounded UTF-8 JSON over authenticated local Unix sockets initially. The proposed **private worker** frame prefix is a four-byte unsigned big-endian payload-byte length, excluding the prefix; zero, oversized, truncated or malformed frames cannot dispatch operations. Partial reads/writes are ordinary transport progress. Handshake precedes all session operations and selects an explicit namespace/schema version, compatible major/minor, endpoint role, feature/profile tuple and limits no larger than either peer's local caps. Unsupported required features or changed meanings fail closed. No autodetection/fallback reinterprets an EA1/public-v1 message as owned-worker semantics.

### Separate namespaces and translation

N0-06 owns public wire definitions, generated bindings, presentation/input fields and public resync behavior in [the public contract](native-contract.md) and [frontend contracts](frontend-contracts.md#one-model-two-useful-clients). Its proposed Rust `experimental_native`, wire namespace `namtab.native.experimental.n0` / version `n0-06-draft-1`, and TS `@project-x/protocol/experimental-native-n0` entry stay separate from historical public-v1 exports. **Private draft proposal:** `protocol::internal_terminal_n0`, namespace `namtab.worker.experimental.n0` / version `n0-09-draft-1`, exported only to reviewed service/worker code and private schema output. Keeper control has its own private endpoint role/version. Existing `internal_engine`/EA1 messages and generated artifacts keep their meanings. The library owns semantic types/versions; neither a public schema version nor a private transport revision silently changes a terminal profile's semantics.

The worker mapper checks wire structure and exact integer/enum/range semantics, then core preconditions/profile/cut/geometry. Service owns authority decisions and public error/projection mapping; worker owns canonical freshness/encoding and returns proposals. These checks are cumulative. Serde/Schemars derives, generated TS validators and import bans alone do not validate runtime peer identity, authorize input, reject every wire ambiguity, cap parser allocation or prove core invariants. Unknown descriptive values may be preserved only where the owning schema explicitly permits it; unknown mutation fields, discriminators or authority-relevant features are refused.

### Private identity and controller binding

Create endpoints in an owned restricted runtime directory. Validate directory/socket ownership and permissions and refuse unsafe replacement/symlink paths; stale endpoint cleanup must establish ownership and absence of a live owner. Check peer credentials as one input and bind the connection to the service-launched worker identity using a fresh private bootstrap challenge/capability sent only on the designated launch channel. Never put that capability in argv, ordinary environment, logs, public DTOs or application output. Possession of a path, PID or same UID alone is not principal/worker authentication. Mutually hostile unrestricted same-UID processes remain outside this assurance; strong isolation needs the verified [runtime profile](../architecture/04-isolation-security-and-approvals.md#filesystem-and-runtime-profiles).

Before accepting a private operation/result, bind the authenticated connection and envelope to: private schema/endpoint role; service controller incarnation and monotonic controller generation; worker identity/incarnation; session ID/incarnation and assigned stream epoch; request/cancellation correlation; and the required profile/engine tuple plus ordered event or expected committed cut. These are private semantic requirements, not a second public DTO definition. Session-local sequence and originating event/ordinal distinguish identical query replies. Service→keeper admission/delivery uses the existing writer/operation identities; worker sequence numbers cannot substitute for them. Reject stale/foreign bindings before applying results; a new connection/restart requires handshake and explicit assignment reconciliation rather than restoring grants from a token or snapshot.

The worker receives only its designated transport FD and reviewed essential runtime FDs; keeper exclusively owns PTY masters. Close-on-exec and an explicit inherited-FD allowlist apply to both worker launch and application exec. A PTY child receives only its authorized slave/stdio and declared resources, never control sockets, store handles or bootstrap secrets; exec setup failure uses a bounded separate status channel and is not reported as successful launch. Reject ancillary FD transfer on normal JSON endpoints. Any later explicit descriptor-passing operation needs separate protocol/ownership review, not a JSON integer interpreted as an FD. Clear unintended capability-bearing environment and avoid ambient service/store paths. A remote bridge later needs authenticated encrypted transport and explicit host/context identity; no unauthenticated TCP port or helper auto-install.

### Bounded decoding, errors and cancellation

Apply limits while receiving/tokenizing, **before** allocating a declared-length buffer, a collection or a generic object map that erases duplicate keys. Validate UTF-8; bound bytes, nesting, key count, array count, string length and cumulative expanded/transient allocation; reject duplicate decoded keys at every object depth, including escaped aliases. Charge key tracking and escaped-string expansion to the same bounded budget. Check arithmetic before multiplication/addition and exact bounded decimal integer conversion. A later schema/DTO validator cannot repair ambiguities or allocations already accepted by an unbounded JSON parser. No operation reaches authority/core evaluation until full frame decoding and validation succeed; no partial frame executes.

For finite adversarial review only, propose `n0-worker-decode-review/0`: at most **1,048,576 payload bytes/frame**, **16 nesting levels** (root container = 1), **64 members/object**, **1,024 elements/array**, **65,536 decoded UTF-8 bytes/string** including keys, **8,388,608 charged transient bytes/frame** including receive storage and decoding/key-tracking/DTO copies, and **8 outstanding frames/connection** within a separately reserved connection/global byte budget. Charge actual allocated capacity and checked representation overhead, not merely payload length. Exact limits and the decoder's accounting model need implementation review and owner resource admission; this tuple is neither a durable snapshot codec profile nor a guarantee that every valid semantic state fits one frame. Chunk/page private projections at committed cuts; never split an indivisible mutation to evade bounds. A valid request lacking reserved capacity returns `ResourceExhausted`; invalid syntax/bounds returns `InvalidRequest` or closes the offending transport without dispatch. The N0-06 public tuple remains separately owned.

Use the [existing typed error families](../engineering/14-repository-and-engineering-practices.md#error-cancellation-and-logging-contracts), preserving admission stage, observation gap and receipt/delivery outcome as separate facts. Malformed frames report bounded sanitized diagnostics without echoing payload/keys; version mismatch is `IncompatibleVersion`, a stale private binding is refused and reconciled, and a lost worker is `Unavailable` while potentially dispatched effects retain their own unknown receipt outcome. No transport error means “safe to retry” or “zero bytes delivered”. Cancelling an observation releases its subscription/credit; cancelling queued work identifies the request and reports the observed stage. An admitted action cancellation follows receipt/keeper reconciliation and does not undo a partial write. Deadlines stop new admission, not already committed effects. Logs/metrics carry opaque identities, bounded queue/work counters and typed codes; exclude terminal/input content, argv/env, bootstrap secrets, serialized DTOs and derived sensitive `Debug` output. Capture consent is a separate path.

Versioned TOML configuration remains declarative, with portable keymaps/themes/profile choices. Separate machine-local paths/secrets and runtime grants. Migrations validate, preserve a backup and fail closed on unsupported security settings; no executing shell snippets during config load. Built-in typed adapters first; later out-of-process versioned adapters receive scoped capabilities. No arbitrary native code loading, generic workflow DSL or premature stable plugin ABI.

## Complete snapshots and journal cuts

Define three different objects: a **presentation snapshot** for live attach; a **complete terminal-state snapshot** for a compatible reducer; and a **product checkpoint** binding that state to runner/store cuts and capture consent. None carries input/dispatch authority or an OS process image. Ordinary reconnect needs the presentation object only. A presentation frame can omit inactive buffers, save slots, parser continuation and hidden modes; it must never be relabeled as a complete terminal snapshot or used to resume reduction. The [owned-state checklist](compatibility-and-core.md#complete-semantic-state) defines completeness for the exact admitted profile, with explicit absent fields for excluded features.

The complete state includes every family admitted by the exact profile in the core table (explicit absent/default state for exclusions), both screens/history, decoder/FSM continuation, discarded-string terminator state, pending grapheme/reflow context, typed negotiation stacks, profile/error/limit behavior and semantic counters. Derived caches such as glyph atlases and search indexes are omitted only when they can be rebuilt without changing semantics. Snapshot between fully reduced ordered events, with no staged semantic mutation or partly consumed event; a partial UTF-8/ESC/CSI/string terminator can still be the state **at** that cut because bytes span events. The [bounded reduction proposal](compatibility-and-core.md#resource-limits-and-failure-policy) withholds partial-event projections and bounds retained progress. “Wait for parser ground” is not required or a complete solution. A background copy binds one immutable committed cut; mixing rows from a newer cut with older parser/mode/frontier state is invalid.

Recommended v1 envelope: explicit product/snapshot schema/codec/engine/profile/Unicode/width versions, session/incarnation, event and stream/geometry cuts, configuration digest, required feature bits, bounded lengths/cell/history counts, explicit completeness and closed/unknown flags, privacy classification and stored-byte integrity digest. Use explicit typed JSON initially, no compression, with quota-checked decoding; benchmark size/copy/parse cost before choosing a binary codec. Before durable import is advertised, review exact serialized-byte, depth, collection and transient-allocation limits in addition to the dev semantic bounds; no unbounded JSON parser or declared count may allocate first and validate later. Those codec limits and the codec/library pin remain N0-08/N4 gates, not an adopted serializer here. A serializer library's version or Rust struct memory layout is not the format. Integrity detects corruption, not an authenticated owner or trustworthy data. Never restore executable commands, FD numbers, leases, approvals, secret capabilities or callbacks from it.

The optional durable journal records ordered output bytes, input delivery metadata, geometry/options and state-relevant controls under the chosen capture policy. Separate control metadata from content; default metadata must not contain terminal payload, content-derived hashes, credentials or environment values. Content digests and artifact references need their own authorized evidence context. Native task output/artifact retention is explicit, not implied by the word “managed”.

Treat literal argv/environment/application input as potentially secret too. Persist safe identity/status/sequence facts by default, not the raw request body or an unconsented payload hash. Volatile payload binding plus namespace/sequence fencing permits conservative duplicate refusal after restart/retention expiry; stronger durable input audit needs separate consent and secret-reference handling. No perfect automatic secret classifier is assumed.

For checkpoint C at event E: bind session/incarnation, stream epoch and exact byte offset after E, geometry/options versions and capture authorization to one complete state; require its processed frontier to be exactly E and its parser continuation to describe precisely that prefix. Verify no gaps/duplicates/reordering in the required journal prefix and retained tail, including geometry/options and EOF records. Serialize an immutable bounded state view; verify all required retained/durable tail events after E; write a temporary object, verify limits/integrity, durably publish object and journal reference using the storage protocol. Account for directory/file sync assumptions and crash/full-disk cuts (S26). Retain the previous valid checkpoint until commit. A reference cannot become usable before its object and required prefix are durable. A product checkpoint additionally records keeper source/delivery and service-store reconciliation references separately from terminal state; their lag/uncertainty must be explicit, never manufactured into one atomic OS cut. A memory-only keeper tail remains bounded and can be lost; do not call it crash-proof.

On restore, reject unknown policy/data/configuration versions, omitted continuation/slot fields, impossible cursor/margin/occupancy/counter values and state/cut mismatch before publishing state. Validate identity/version/profile/quotas/completeness, replay the exact ordered tail in **no-external-effects mode**, and reconcile keeper delivery frontiers. Generate a new authority epoch and require fresh input ownership. Historical queries may update internal query state as specified, but never re-emit old replies, input, launches, clipboard or window effects. Reply/operation IDs and delivery-unknown outcomes remain in the separate receipt log; identical future live queries remain valid. A state hash or plausible screen does not authorize replay of an uncertain external write. Receipt admission/consumed-sequence fences and delivery records are independent of terminal snapshots; a terminal snapshot cannot roll them back or authorize dispatch. Restore/replay never resends uncertain operations, and loss of receipt-identity continuity retires the affected namespace. This is a required cross-contract seam with the [native receipt contract](native-contract.md#minimal-operations-and-asynchronous-outcomes), not an implemented recovery algorithm.

## Precise v1 recovery contract

| Failure / policy | v1 target behavior | Non-guarantee |
| --- | --- | --- |
| Late attach, frontend restart or disconnect; owner alive; capture off | Fresh presentation snapshot + deltas from its cut; new view is read-only until ownership granted | No need for full output replay; no promise of retained old scrollback beyond quotas |
| Engine worker dies; capture off | Mark interpretation unknown, fence all application input, keep separately observed process status; offer new session/authorized process controls | No reconstructing arbitrary live TUI from nothing, repaint guessing or raw-input bypass |
| Worker dies; authorized valid exact-version checkpoint + complete retained tail | Restore/replay without effects, verify cuts and reobserve, then allow fresh ownership | Missing bytes/options/identity, corrupt/oversized state or uncertain delivery stays unknown |
| Service restarts, keeper/engine survive | Reconcile receipts/controller epochs and current state before admission | Old grants/leases/queued actions do not resurrect automatically |
| Keeper/PTY/process loss, reboot | Report observed exit/loss or unknown outcome and preserve authorized evidence | A terminal snapshot cannot restore processes, files, remote side effects or old FDs |
| Capture revoked / retention expired / unsupported schema | Stop future authorized persistence, apply retention/deletion rules, expose unavailable recovery | No recovery promise from filtered or gapped capture; no guaranteed physical erasure from backups/OS media |

**v1 complete-state guarantee to earn:** continuation equivalence for admitted profiles, exact snapshot schema/engine/profile/data tuple, ordered event tail and validated resource bounds, including arbitrary partial-parser cuts. This is an acceptance criterion, not current proof or all-input formal verification. Initial cross-version loading is refused. Version numbers reserve migration discipline; they do not promise every future format can restore every past live process. A first schema change must deliver a separately reviewed offline migrator with old fixtures/continuation tests or explicit unsupported status. Presentation/evidence metadata should remain inspectable without executing historical engine binaries.

No-capture means no namtab durable raw-equivalent state by default. Cells/history/partial parser snapshots can contain secrets; memory-only is not a claim of no swap, core dump, outer-terminal recording or host administrator access. Engine-loss recovery without durable capture may later use a separately surviving authorized memory snapshot/tail, but v1 does not depend on that extra replica or silently promise it.

A compatibility-worker failure does not by itself invalidate an independently observed pipe-process exit or the service's task/receipt metadata. Mark the lost interpretation and its dependent actions/evidence unknown; retain other authoritative facts. Unrelated native pipe attempts need not acquire a terminal dependency merely because the product is called a terminal engine.

## Threat model and mitigations

[Security and approvals](../architecture/04-isolation-security-and-approvals.md) owns the product threat model, grants and verified runtime profiles. This table specializes that model for owned-core/state/IPC attack surfaces; it does not define another approval lifecycle.

| Threat | Boundary / proposed response | Residual risk |
| --- | --- | --- |
| Hostile escape/Unicode/font/output floods | Pure bounded core, arithmetic/geometry/string caps, fair scheduling, process memory/CPU containment, fuzzing; browser/font parsing outside engine semantics | Safe Rust does not bound CPU/allocations or prove logic correct; process isolation is not a full sandbox |
| Prompt injection / spoofed integration / fake approvals | Output is labeled data; native control uses authenticated typed methods; shell markers remain hints; separate trusted chrome and protected decision channel | Agents can still reason incorrectly from hostile data; renderer text cannot establish human presence |
| Secret entry and capture | Scoped observation grants, explicit protected handoff, no default input logging, raw-equivalent checkpoint consent, bounded retention/export | Echo-off/prompt heuristics cannot identify every secret; outer host and uncontrolled programs may capture it |
| Agent escapes or uncontrolled filesystem/PTY writes | Runtime profile, worktree/mount policies, restricted FDs/sockets/network, mediated keeper channel; enforce and test before claiming restricted execution | Same-UID unrestricted processes may bypass coordination; tasks/leases are not an OS security boundary |
| Forged peers / stale authority / replay | Restricted sockets, peer binding, epochs, operation IDs, bounded receipts, fresh challenge and context-bound approvals | Mutually hostile code with the human's full UID authority is outside this assurance; stronger isolation requires OS enforcement |
| Malicious snapshot/config/plugin | Version/length/structure/integrity validation, no object deserialization into capabilities, inert imports, built-in adapters first | Authenticated content can still be hostile; checksum is not provenance or authorization |

Rootless restricted runtimes remain the existing recommended enforcement direction, subject to host prerequisites and negative tests. Host-approved unrestricted execution is a separately labeled profile, never described as sandboxed. No system configuration or isolation experiment is part of this campaign. Shutdown/takeover stops future mediation only to its tested boundary; existing child/remote side effects require separate controls and evidence.
