# namtab manifesto

**North star: an AI-first execution and coordination harness around a custom owned terminal engine.** [ADR E5](../adr/0005-ai-first-harness-direction.md) owns the chosen direction and open choices. These principles guide tradeoffs; they are not claims of achieved scale, speed or compatibility.

- **Build the agentic backbone.** Coordinate identified agent runs, shared task contracts, dependencies, workspaces, artifacts and evidence. Structured operations and attributable results reduce ambiguity; interactive terminal navigation remains a core capability for existing tools.
- **Own the semantics.** The Rust engine owns authoritative state, mode-aware input, receipts and authority; the native harness consumes its contracts. Reuse suitable OS, text, font and rendering infrastructure without delegating native truth to prompt parsing or a legacy emulator. UI, output and model messages never confer authority.
- **Scale useful work and human oversight together.** Aim for dozens of agents with bounded scheduling, fair queues, targeted observations and explicit integration. Connected agents, running commands, PTYs and model requests are different resource populations. Human steering, exception review and focused activity windows must remain understandable without a wall of panes.
- **Make responsiveness architectural.** Rust enables low-overhead implementation, not proof of faster outcomes. Measure end-to-end p50/p95/p99 for control, observation, input and actual paint separately from inference/application latency. Include all processes, queues and storage. Reserve human takeover/control, bound memory and apply backpressure/cancellation without hiding unknown effects. The exact harness workload and numerical gates remain open; inherited G6 numbers are reference proposals.
- **Show evidence and uncertainty honestly.** Bind task, operation, stream and artifact facts to exact identities/revisions/context. Distinguish reported status, delivered input, observed transition, process exit and accepted result. No automatic retries after uncertain side effects, no fabricated model progress, and no universal semantic understanding of opaque TUIs.
- **Keep human control excellent.** The custom emulator serves steering, ordinary terminal interaction and safe intervention. Native-window feasibility before toolkit selection is approved for design; final form/renderer remain open. Electron is outside active product scope, and the retained host TUI is diagnostic/attach tooling. Keyboard ergonomics, accessibility and clear ownership are requirements for whichever interface is selected. Takeover does not undo prior effects.
- **Build for sustained ownership.** Maintain cohesive modules, narrow versioned contracts, reviewed dependencies, reproducible provenance and logical testable commits. Prefer a bounded real proof over speculative infrastructure. Keep negative evidence and repair fundamentals before expanding scope.

Non-goals: universal compatibility, perfect isolation/security, deterministic execution replay, inferred cognition or task success, faster model inference through terminal engineering, and speed superiority inferred from Rust. No framework, standalone-window form, exact 32-client workload or model provider has been selected by this direction.

Current reality: main includes the finite owned engine, native feedback/lifecycle and bounded ENG1/NAT1 increments. Two scripted clients and real process/native control are evidenced; actual model mediation, dozens-agent scale and full NG1 remain unqualified. Electron is removed; original X4/EA1 FAIL evidence and earlier MK1 history remain. [Architecture](../architecture/index.md), [user guide](../users/index.md) and [roadmap](../engine/delivery-and-validation.md#engine-and-native-harness-workstreams) distinguish current operation from proposed qualification. These principles grant no task or merge authority.
