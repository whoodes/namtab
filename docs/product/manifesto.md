# Project X manifesto

**Draft north star.** Build an agent-first terminal that remains an excellent ordinary terminal for people. Use these principles to decide tradeoffs; they are requirements and priorities, not claims that the current prototype has achieved them.

- **Make human and agent interaction first-class.** The host-terminal TUI and Electron desktop serve the same supervised sessions, with honest capability differences. Ordinary Linux shells, CLIs, TUIs, editors, REPLs and OS/library environments remain useful without agents, Zsh or a prompt integration. Neither frontend becomes the authority.
- **Supervise work, not a wall of panes.** Organize parallel agents around tasks, artifacts, dependencies, decisions and reviewable outcomes. Progressive disclosure, keyboard ergonomics, accessibility and a bounded attention budget must help a person understand what needs intervention as concurrency grows.
- **Let agents navigate real tools.** Support arrows, completion, modifiers, function keys, paste and interactive navigation through explicit session-bound observe–act–observe loops. Keep terminal UI commands, application keystrokes and automation APIs distinct. Human-like interaction does not give an agent universal understanding of an opaque application's state; stale screens, lost keys and ambiguous transitions stay visible.
- **Make responsiveness an architectural requirement.** Rust enables a low-overhead core; language choice is not proof of lower latency or superiority. Measure terminal/control, observation, input admission/encoding and actual rendering separately from model inference and application execution. Report end-to-end p50/p95/p99, including queueing and visible paint, on declared hardware/workloads for TUI-only, desktop-only and both together. Keep expensive parsing, storage, indexing, snapshots and model work off interaction paths through bounded scheduling and explicit handoffs, not unbounded parallelism. Prioritize human input and takeover while preserving fairness, bounded queues/memory, backpressure and explicit cancellation/unknown outcomes under floods. The [provisional G6 budgets and reference workload](../engineering/07-validation-roadmap-and-risks.md#performance-and-resource-budgets) and [all-process measurement protocol](../engineering/16-test-and-ci-strategy.md#all-process-performance) remain the numerical baseline; no achieved benchmark or new SLO is implied here.
- **Show evidence and uncertainty honestly.** Bind observations, approvals and validation to exact identities, revisions and execution contexts. Separate delivery, observed transition and completed effects. Gaps, partial output, unavailable evidence and unknown outcomes must not turn into fabricated success or automatic retries. Untrusted output and shell markers remain data.
- **Keep control understandable.** Make writer ownership, approval context, takeover and resume explicit. Human override fences future mediated input; it does not undo work already dispatched or stop every side effect. Capture consent, secret handling and runtime isolation are separate boundaries with separately verified guarantees.
- **Build for sustained ownership.** Keep module responsibilities clear, contracts versioned where needed, and extension points justified by real variation. Prefer maintainable public seams and reproducible provenance over private shortcuts. Deliver logical, self-contained, testable commits so reviewers can reason about changes, rebase authorized future work and locate regressions. Retain failed gates and repair fundamentals before expanding scope.

Our non-goals are universal compatibility or opaque-TUI semantic understanding, perfect security, deterministic execution replay, faster model inference through terminal engineering, and speed superiority inferred from Rust. Pane count, plugin count and demos are not measures of success. When tradeoffs arise, preserve truthful control and evidence, then test the smallest design that can meet the existing human-experience and performance gates. Do not relax correctness to win a latency chart.

Current reality: the [bounded EA1 selection gate fails](../engineering/21-ea1-native-worker-results.md), original X4 remains failed, and no full terminal/frontend or performance qualification exists. This manifesto changes no engine choice, gate verdict or implementation scope.
