# MK1 local broker

`namtabd` is a supervised, same-UID Linux developer-host prototype. It is not a sandbox, a production authentication boundary, NG1, or durable terminal recovery. The worker owns the only terminal reducer; the broker alone holds PTY writers and admits typed input. Clients receive canonical text lines, native stream/process facts and metadata receipts.

Build the actual matching private binaries before broker tests:

```sh
CARGO_HOME="$PWD/.cache/cargo" cargo build --offline -p project-x-terminal --bin namtab-terminal-worker -p project-x-platform --bin namtab-pty-helper -p project-x-service --bin namtabd
CARGO_HOME="$PWD/.cache/cargo" cargo test --offline -p project-x-service --bin namtabd
CARGO_HOME="$PWD/.cache/cargo" cargo clippy --offline -p project-x-service --all-targets -- -D warnings
```

Launch with absolute paths:

```text
namtabd --socket PRIVATE_DIRECTORY/socket --workspace WORKSPACE --worker WORKER_BINARY --pty-helper HELPER_BINARY [--terminfo LOCAL_TERMINFO_DIRECTORY]
```

The existing socket directory must be owned by the effective UID with mode 0700. A newly created final directory is made private. The socket is mode 0600; Linux peer credentials must match the daemon UID. An existing socket is refused and never unlinked. Normal-return cleanup removes only the socket inode created by that server. Abrupt termination may leave a socket; the prototype deliberately refuses to guess ownership/liveness and remove it automatically. Use a fresh private run directory after an abnormal stop. Managed children or descendants may remain alive after an abrupt daemon kill; a fresh daemon does not restore or terminate them. Operator process cleanup is separate. No global terminfo or runtime configuration is installed.

A provided terminfo directory selects the separately reviewed `namtab-mk1` entry. Without it, the shell truthfully uses `TERM=dumb`, with its capability limit disclosed in the static client/documentation profile notice. `Snapshot.degraded` is reserved for operational faults that fence input; a healthy developer-host profile reports null. Bash starts with `--noprofile --norc`, controlled PATH/locale/HOME/PS1 and disabled inputrc, history and startup hooks. The environment is cleared; caller credentials and shell startup files are not inherited. Child filesystem/network execution remains unenforced developer-host execution.

## Fixed admitted bounds

- At most four live client connections and sixteen retained endpoint identities per daemon. This supports repeated client launches without evicting old endpoint ownership, resume tokens or receipts. Snapshot endpoint status lists ID, declared role and current connection state only; it exposes no resume token/label and proves no physical human presence or agent cognition. A live RAM-only resume token reconnects one endpoint, retaining ownership and receipts; only one connection may bind that endpoint. No token or old epoch restores authority after a daemon restart.
- At most **two total PTY sessions and two total managed argv attempts per daemon**, including completed records. This intentionally simple MK1 lifetime limit requires an explicit fresh daemon namespace for more; restarting does not restore processes, screens or old input authority.
- PTYs start at 80 columns × 24 rows, with explicit writer resize within 2–160 columns × 2–48 rows. Passive views never fight over geometry.
- Each endpoint retains at most 4,096 mutation receipts and volatile SHA-256 body bindings. Canonical mutation bodies are capped at 64 KiB. The snapshot includes only the last 16 own receipts; `receipt` can query every retained one. Reaching an ordinary receipt cap latches all new-effect admission closed until an explicit fresh daemon namespace; none are evicted or silently retried. One additional reserved RAM emergency receipt per endpoint can record a protective authority decrease, with unknown durability, without granting a new writer.
- Public NDJSON bodies are capped at 1 MiB and decoded through the owned MK1 typed decoder. Connections issue one request at a time. Worker queues are bounded to eight requests, with one actor, one response reader and a two-second fail-closed RPC deadline. No worker restart or interpretation replay occurs automatically.
- PTY output enters the worker in at most 512-byte acknowledged events. Worker views are structurally checked before publishing; the worker remains the sole semantic authority. Input encoding and final writing share exact ownership, generation, mode and freshness checks. Human `human_live` policy tolerates ordinary echo changes only and may wait on the same reserved operation for a pending canonical ACK before encoding and before its first OS write, with one overall 250 ms pre-write deadline. Waiting releases the state mutex, rechecks original mode/owner/generation on every wake, never grants a quiet-window guarantee, and never resends bytes; a continuous flood can still refuse with zero effect. agents require exact observed screen revision. Human forced takeover bumps the generation without awaiting the worker. Required journal fsync and kernel calls may still block; there is no hard responsiveness claim.
- Text/paste content is capped at 8,192 UTF-8 bytes, but the platform single-write cap also includes encoded wrappers. Bracketed paste therefore admits at most **8,180 content bytes**; a larger encoded operation refuses before writing. There is no raw-byte bypass. Partial writes disclose only the exact accepted prefix, fence further application input and never automatically send a suffix. Applied input means local PTY acceptance, not application consumption or command completion. A new session is the bounded recovery path after uncertain input; MK1 does not guess a repaired application parser state.
- Managed stdout and stderr retain at most 64 KiB each in RAM and continue draining after truncation. Safe bounded text projections escape controls; they are not raw byte archives. Observed child exit and stream EOF are distinct, including an explicit draining state. Only the direct child is owned; descendant/remote cessation is not promised.
- At most 16 explicit artifact references, each an observed regular file of at most 1 MiB inside the startup workspace. Opened descriptor identity is checked before reading. Validation requires a declared human endpoint in this trusted-host profile, not a proof of physical human presence. A SHA-256 revision and validation refer to a bounded file observation; they are not a sealed-tree, command-causality or correctness proof. Later observed changes mark validation stale.

## Metadata reservation and failure behavior

Normal public mutations reserve a receipt and fsync metadata before their effect. The sole exception is a strictly checked protective human force-revoke or current-writer release when storage/cap admission has failed: it clears ownership and bumps the generation, grants no new writer, and reports an unknown-durability receipt in the one reserved emergency RAM slot. The daemon remains latched against future grants, application input, query writes and launches until explicit restart. The append-only journal contains epoch/endpoint/request/operation/state/delivery extent only: no argv, input, output, full request or raw body hash. The body hash exists only in volatile RAM for duplicate/conflict detection. Completion updates are fsynced separately; loss of completion persistence remains unknown, never safe to retry.

The owned journal is capped at **32 MiB across daemon epochs**, is mode 0600, and is never truncated or silently deleted. Existing files must match the owned format/UID/mode/inode checks. New journals use exclusive creation and the parent directory is synced. Pending old reservations are reconciled to unknown on a clean journal reopen; a new daemon epoch still rejects all old tokens. A malformed or partial journal refuses startup. Full/unavailable reservation storage refuses new effects, and completion-write failure discloses uncertainty.

Worker loss marks every associated interpretation unknown, closes ownership, and turns pending receipts unknown. Independent observed process/pipe facts survive; the child is not reported stopped merely because the worker failed. New dependent mutations refuse. Capture remains off; journal metadata and bounded live stream display are distinct from durable terminal capture.

The real integration harness covers PTY shell execution and typed IO, stale observation refusal, forced takeover while the worker is SIGSTOPed, final writer rechecking, duplicate argv launch suppression, separate streams/exit/drain/truncation, artifact revision staleness, endpoint resume and old-token refusal, worker-loss fencing, journal reconciliation/cap refusal, and inode-specific socket cleanup, real UTF-8 completion at PTY EOF and protective revoke with full journal storage. Headless tests do not certify actual frontend keyboard, paint, IME, accessibility, OS containment, full NG1 or v1.

The retained endpoint, receipt and journal limits are included admission bounds, not a promise that every maximum can be occupied simultaneously. Reaching sixteen retained identities refuses a new identity; existing live-epoch resume remains available without deleting old evidence.

## Shared immutable tasks and launch attribution

MK1/1 advertises additive `shared_tasks_v1`, `attempt_origin_v1` and `receipt_results_v1` capabilities in the canonical snapshot. A missing capability list means an older service has not attested support. Existing ad-hoc `run` JSON remains valid when it omits `task_revision`; old clients ignore new response fields. Updated Rust clients default missing response extensions to empty/unknown rather than inventing authority. This is an experimental live-wire addition, not a native replay or durable recovery guarantee.

`define_task` declares at most four immutable RAM-only contracts per daemon: `task` is the existing 1–80 printable-ASCII-byte label, `goal` is nonblank and at most 512 UTF-8 bytes with no control characters, and `expected_artifacts` contains at most two relative slash-separated normal-component paths of at most 512 bytes each. Empty, dot, parent, absolute, backslash and control-character paths refuse; `.artifacts/result` is a permitted normal path. Expected files need not exist and are declarations only. They do not schedule work, validate artifacts, seal a workspace or establish command causality.

The service hashes a domain-separated canonical definition to a `sha256:` revision held only in RAM. Identical definitions reuse the same contract/revision; changing a registered goal or expected-path list refuses, and contracts are never evicted or edited. A `run` naming a registered task must supply its exact observed `task_revision`, including when an older client would omit it. A provided revision for an unknown task refuses. An ad-hoc attempt admitted before a same-label contract is defined retains a null revision forever. Task registration does not reserve either of the two total managed-attempt slots.

Each successful managed launch publishes `Attempt.origin = {endpoint, request_id}` directly from the bound requesting endpoint and reserved mutation, plus the exact admitted task revision or null for an ad-hoc label. Each launching receipt carries typed `result = {kind: "attempt_started", attempt: ID}`; task-definition receipts carry `{kind: "task_defined", task, revision}`. Clients correlate by those references and explicit origins, never by snapshot arrival order, latest attempt or a reused request ID across different endpoints. Applied launch still means local process creation, not task completion. A completion-persistence failure retains the attempt reference with an unknown receipt; it never authorizes retry.

Two declared agent endpoints can observe the same contract and independently launch attributed managed attempts. Existing writer `release_control` followed by another endpoint's `take_control` remains the explicit terminal handoff; a shared contract grants no writer lease. There is no scheduler, dependency graph, autonomous model, task-completion inference or expanded process allowance. Goals, expected paths, revisions, argv and typed result payloads stay out of the metadata-only journal; capture remains off. Existing receipt deduplication, role/generation/mode fences, four live connections and sixteen retained identities remain in force.
